# Worker — Cloudflare API for LunaClair

## Purpose

- The `api` Cloudflare Worker (`https://api.project-lunaclair.workers.dev`) is the only bridge between the LunaClair PWA and Cloudflare D1 (serverless SQLite).
- Browser code never calls D1 directly; all cloud data flows through this Worker's HTTP API.

## Ownership

- This Worker owns the D1 schema, migrations, and the REST API contract for cloud sync and content distribution.

## Local Contracts

- Config: root `wrangler.jsonc` — Worker name `api`, D1 binding `DB` (database `lunaclair`), migrations dir `./worker/migrations`, `nodejs_compat` enabled, and **`observability.enabled: true`**, which is what makes `console` output retained and queryable in Workers Logs rather than only visible live through `wrangler tail`.
- Endpoints:
  - `GET /health` — liveness + D1 connectivity probe (503 when D1 is unreachable).
  - `POST /api/sync/push` — Ingest client sync mutation envelopes (`{ deviceId, mutations }`). Each mutation supplies `clientTimestamp`, which drives Model A LWW timestamp reconciliation for `highlight`, `drawing`, `flashcardReview` (`user_entities`). Enforces idempotency via `sync_idempotency`, Model C atomic CAS optimistic versioning for `document` (`user_documents`), and Model B append-only event stream for `quizSession`. Returns `{ accepted, conflicts, rejected, serverCursor }`. `Authorization: Bearer <token>` is authoritative for user identity (JWT `sub`/`userId` or raw token string) with fallback to `x-user-id` and `'user_default'`. It also carries the idempotency-ledger retention pass (see the retention contract below), best-effort so it can never fail an otherwise successful push.
  - `GET /api/sync/pull?cursor=...&limit=...` — Delta pull query on `sync_changes` where `sequence > cursor` with batch hydration from `user_documents` and `user_entities`. Returns `{ newCursor, hasMore, changes }`. Identifies user via authoritative `Authorization: Bearer <token>` or fallback headers.
  - `POST /api/shares` — Publish a StudyPackage snapshot payload to Cloudflare D1. Validates package format (`lcpack`), schemaVersion (`1`), prefix naming, question type, per-type question payload structure, foreign key relational integrity, asset references, material `tags` (optional `string[]`), and question `sourceSection` (optional `string`). Enforces 5 MB payload limit. Supports `accessType: 'public' | 'unlisted' | 'passcode'`. Passcodes are hashed with SHA-256 before persistence. Returns `{ id, format, schemaVersion, title, accessType, shareUrl, createdAt }`. **`sourceSection` is additive and optional: absence is valid and stays valid (no version bump, no existing share stranded), and only a present-but-non-string value is rejected** — the same rule the client validator applies, deliberately, because a package the app can publish must be a package this endpoint accepts or publish and import disagree. **Per-type payload validation, and there is ONE tier on both sides:** a structurally malformed payload (a `fill_in_blank` whose `___` count disagrees with `blanks.length`, an unanswered `multiple_choice`/`multiple_select`, a `true_false` with a non-boolean answer, …) is refused here **and refused identically by the client on import**, so malformed content cannot enter the system by either route. The client once had a tolerant *import* tier that admitted such a payload and reported it, so shares published before payload validation existed would stay cloneable; **that population was proven empty** — a read-only query of the remote D1 `shares` table found the table itself was never created there, so no `.lcpack` had ever been published — and the tier was **deleted, not kept as an unused mode** (a switch with one reachable value misrepresents the contract to the next reader). See "Evidence Before Compatibility" in the root `AGENTS.md`. The rules and their wording remain a byte-for-byte mirror of `src/domain/quiz/validation/questionPayloadValidation.ts` (the Worker cannot import the client module); `worker/src/__tests__/questionPayloadParity.test.ts` is the guard, asserting the same verdict and the same messages across a valid/invalid corpus of all five types.
  - `GET /api/shares` — Public discovery feed endpoint (`handleListPublicShares`). Filters strictly on `access_type = 'public'` and non-expired shares. Projects lightweight summary (`id, format, schemaVersion, title, description, author, viewCount, downloadCount, createdAt`) without the full JSON payload. Supports text search `q`, sorting (`popular` | `recent`), limit capping (1-50, default 20), and opaque base64 keyset cursor pagination (`nextCursor`, `hasMore`).
  - `GET /api/shares/:id` — Resolve a published StudyPackage snapshot. Verifies expiration and passcode (via constant-time XOR comparison with `X-Share-Passcode` header). Increments `viewCount` atomically and returns `{ id, format, schemaVersion, title, description, author, accessType, package, viewCount, downloadCount, createdAt, updatedAt }`.
  - `POST /api/shares/:id/download` — Increment download counter on a published share.
  - `DELETE /api/shares/:id` — Delete a published share. Enforces creator ownership via `Authorization: Bearer <token>` / `x-user-id` or seed token.
  - `GET /api/ai/models` — Serves the **public model catalog** (`handleAiModels` → `toPublicAiModelCatalog`): `{ version, availability, defaultModelId, models[] }`, each model carrying `id`, `display`, `contextWindowTokens`, `maxOutputTokens`, `maxDocumentContextChars`, `supportsVision` (`boolean`), and `pricing` (`null` = free). Provider routing data (`provider`, `providerModelId`) is projected away — the client selects by catalog `id` and never learns a provider. **Unavailable models are omitted, never listed to be refused** (the picker must not offer a choice the endpoint will reject). `defaultModelId` is `null` whenever the default is not actually servable, so a client never inherits a choice the endpoint would refuse. Availability is server-controlled by **two independent switches** over `wrangler.jsonc` vars: `AI_DISABLED_MODELS` (comma-separated catalog ids) is the per-model no-deploy kill switch, and `AI_CHAT_DISABLED` (`true`/`1`/`yes`/`on`) is the **incident switch** that stops the assistant entirely — including the default, which is why the per-model switch no longer exempts anything. A registry row's `available: false` is the deploy-time retirement. The global switch still answers **200** with `availability: 'disabled'` and an empty `models`, because the client has to tell "intentionally off" from "cannot reach the endpoint". An unknown id in `AI_DISABLED_MODELS` is logged and ignored rather than silently trusted. An absent model id means the default; an **unknown** id is refused rather than substituted, because a silent substitution would bill the user for an answer they did not ask for. Two models are registered: `cf-llama-3.3-70b` ("Standard", Workers AI, default, vision unsupported) and `ukisai-swift-max` ("MAX", a 256k-window hosted endpoint served through the `ukisai` provider, vision supported). **There is no fallback model.** The previous silent retry named `@cf/meta/llama-3.1-8b-instruct` (Cloudflare deprecated it 2026-05-30), so a provider failure could surface as an unrelated second failure; failures now return a coded status — `AI_DISABLED` (503, the deployment has switched the assistant off; checked before the request body is even read), `MODEL_UNAVAILABLE` (400), `PROVIDER_UNAVAILABLE` (503, the model's provider is not configured), `CONTEXT_LIMIT` (400), `RATE_LIMITED` (429, with `retryAfterSeconds` when the provider states a wait), `TIMEOUT` (504, a provider that accepted the request and then went silent), `ABORTED` (499, the client itself cancelled — never dressed up as an upstream failure), `UPSTREAM_ERROR` (502) — alongside the human-readable `error`. A replacement model is a registry row, never a retry branch.
  - `POST /api/ai/chat` — Streaming chat completion, normalized to app-native SSE events and dispatched to the **provider that serves the requested model** (`resolveAiProvider` → `worker/src/ai/`). A request may name a model (`model`, a catalog `id`); the registry entry's own facts drive the invocation — its `maxOutputTokens` is the request's `max_tokens` and its `maxDocumentContextChars` bounds the study material embedded in the prompt, so the served document cap is a model fact rather than a literal. Supports multimodal vision payloads with structured `content: AiMessageContent` (`{ type: 'text' | 'image_url' }`). If any message includes image parts, the handler validates that the model supports vision (`supportsVision: true`, rejecting non-vision models with 400 `MODEL_UNAVAILABLE`), enforces single-page image payload limits (batched multi-image requests rejected with 400 `BAD_REQUEST`), validates image data URLs (`data:image/(jpeg|png|webp);base64,...`), and enforces a 3MB binary payload cap. Structured parts are passed directly to the provider adapter (`ukisai.ts`), and telemetry logs `hasImages: true` without leaking image data. The Worker composes the system prompt server-side (mode framing + study material + selection), appends any client `system` messages as task instructions, merges consecutive same-role turns, and re-emits the provider's stream as app-native events (`start` / `token` / `done`). One provider event is pulled **before** committing to a 200, so a rate limit, context rejection, or configuration failure keeps its own status and code instead of arriving as a success whose body holds an error; a failure after text has started becomes an app-native `error` event followed by `done`. A model disabled by either switch is refused here as `MODEL_UNAVAILABLE` (or `AI_DISABLED` for the global one) — the same filtering that built the catalog, so the two can never disagree. **Every provider pull is bounded by two deadlines** (`worker/src/ai/deadline.ts`): `AI_FIRST_EVENT_TIMEOUT_MS` (25s) until the first event, deliberately tighter than the client's own 30s first-token watchdog so the **Worker wins that race** and its coded, model-attributed `TIMEOUT` is the message the user sees; then `AI_STREAM_IDLE_TIMEOUT_MS` (45s) between events, an *idle* bound rather than a total-duration cap, so a long answer that keeps producing tokens may stream indefinitely while one that stops producing fails instead of holding the response open. Providers that can cancel their own outbound request honor `AiProviderRequest.connectTimeoutMs` and `signal` (the UkisAI adapter drops the composed signal once headers arrive, so the deadline covers becoming responsive, not the whole answer); the route independently enforces it per pull, so an in-process binding that cannot be cancelled still cannot hang the response — and a pre-stream timeout keeps its own 504 rather than committing to a 200. **A deadline or a disconnect actually cancels the work, it does not merely abandon the promise**: the route owns a provider `AbortController`, calls the generator's `iterator.return()` (unawaited, so a provider that ignores the signal still cannot hold the response), and skips every later write once the consumer is gone — an `enqueue` on a cancelled stream would throw and turn a clean stop into an errored one. The same release runs when the client request aborts (499 `ABORTED`) and when the response consumer cancels the stream. A request abort **also marks the stream cancelled** rather than only aborting the provider: the runtime is not required to call the stream's own `cancel()` when a request goes away, so without that an `error`/`done` could still be written into a response nobody is reading. The terminal `done` event carries **the provider's own token usage and the serving model's catalog id** so the client can attribute real cost; `core/aiUsage.ts` owns the snake_case → camelCase normalization, and `usage` is omitted (never zeroed) when the provider reports none. It **refuses a request at the model's context window minus `max_tokens`**: Cloudflare validates estimated input *plus the request's reserved output* (`5021: The estimated number of input and maximum output tokens (8810) exceeded this model context window limit (8192)`), so the prompt budget the client meters is exactly `window − max_tokens` rather than a safety margin. A stream that produces no text is reported as `emittedTokens: 0` on that request's telemetry record and separately warns with a sample of the offending payload, because a 200 that yields nothing is otherwise indistinguishable from a hang on the client. **Failure classification never rests on prose alone**: the shared classifier prefers an HTTP status, then a provider-declared error `type`/`code`, then an observed numeric platform code (declared or prefixing the message), and reads the message only as a last resort — so reworded upstream text cannot silently reclassify a context rejection as a generic upstream error. `retryAfterSeconds` likewise prefers the `Retry-After` header and falls back to the provider's "Try again in Ns." phrasing.
- CORS: allowlist via the `CORS_ORIGINS` var (comma-separated). Empty or unset allows any requesting origin (`*`) with credentials-safe origin reflection for dev (5173/4173) and production; specified origins enforce an exact allowlist match.
- Pages integration: Cloudflare Pages reverse-proxies all `/api/*` traffic to the Worker via the edge Function in `functions/api/[[path]].ts` (Vite dev server proxies locally via `vite.config.ts`).
- Timestamps: **all D1 timestamps are ISO-8601 UTC text strings** (`YYYY-MM-DDTHH:mm:ss.sssZ`), matching the domain/Dexie representation so nothing converts formats across the API boundary. Stamped server-side via `new Date().toISOString()`; the one client-supplied exception is the sync push `clientTimestamp`, which drives Model A LWW reconciliation (server time is the fallback when absent). `createdAt` is set on first insert and preserved on re-upsert (only `updatedAt` changes).
- Routing & Architecture (ADR-016):
  - Zero-framework, layered architecture using native Web Standards (`Request`, `Response`, `URLPattern`/segment matching).
  - `worker/src/index.ts` is a slim composition root (<30 lines) orchestrating CORS preflight, header computation, router dispatch, and global 500 error boundary.
  - `worker/src/router.ts` is the declarative router mapping method + path to route handlers, extracting params into typed `RouteContext`, and enforcing 404 Not Found and 405 Method Not Allowed (with `Allow` header).
  - `worker/src/core/` houses foundational primitives: `cors.ts` (origin reflection), `responses.ts` (typed HTTP responses), `security.ts` (timing-safe comparison, bearer token parsing, user resolution, passcode hashing), `path.ts` (anti-traversal segment decoding, cross-realm binary conversion), `aiModels.ts` (the server-owned model registry: internal `AiModelRoute` records with provider routing facts plus the public `AiModelCatalog` projection; `resolveDisabledAiModelIds`/`isAiChatDisabled`/`isAiModelServed`/`listServedAiModelRoutes` are the single availability filter the catalog and chat both read), and `types.ts` (`Env`, `RouteContext`, `RouteHandler`).
  - `worker/src/ai/` houses the internal **AI provider boundary**: `types.ts` (`AiProvider`, normalized `AiProviderEvent`, `AiProviderRequest`, typed `AiProviderError`), `errors.ts` (the shared failure classifier + normalizer, **structured signals first**: HTTP status, then a provider-declared `error.type`/`code`, then an observed numeric platform code — including one that only prefixes the message (`5021: …`) — and only then message prose, so a wording change cannot reclassify a failure), `sse.ts` (the shared `data:` line reader, cancelling the reader on abort so a pending read settles and the generator can unwind), `telemetry.ts` (the one structured record per request, described below), `deadline.ts` (the two pull deadlines — `AI_FIRST_EVENT_TIMEOUT_MS`, `AI_STREAM_IDLE_TIMEOUT_MS` — plus `createTimeoutSignal`, `withIdleDeadline`, `AiStreamTimeoutError`; `withIdleDeadline` races one pull and runs the caller's `onTimeout` **before** rejecting, which is how "abandoned" becomes "cancelled"), `workersAi.ts` (Workers AI over the native binding), `ukisai.ts` (the OpenAI-compatible Swift endpoint), and `providers.ts` (`resolveAiProvider` — route + env → provider, `undefined` when unconfigured). Only the route knows SSE framing; only a provider knows a vendor's payload shape, so adding a provider never touches `routes/ai.ts`.
  - `worker/src/routes/` houses focused endpoint handlers: `health.ts`, `ai.ts`, `sync.ts`, `shares.ts` (the retired `documents.ts`/`figures.ts` handlers were removed with the Phase 12 catalog retirement).
  - Zero barrels: direct file imports only within `worker/src/`.
- Types: run `npm run types:worker` (`wrangler types`) after any change to `wrangler.jsonc`; the generated `worker/worker-configuration.d.ts` is committed.
- Schema: 5 tables defined in `worker/src/schema.ts` for sync and sharing (`user_documents`, `user_entities`, `sync_changes`, `sync_idempotency`, `shares`; the legacy content tables — `documents`, `figures`, and the catalog/quiz tables `subjects`, `terms`, `subject_terms`, `materials`, `questions`, `quizzes`, `quiz_questions` — were dropped in the Phase 12 catalog retirement, migration `20260906121438_curious_lake`):
  - `user_documents`: User documents with CAS optimistic versioning (`user_id`, `document_id` composite PK, `version`, `title`, `content`, `updated_at`, `deleted_at`).
  - `user_entities`: Generic key-value store for domain entities (`user_id`, `entity_type`, `entity_id` composite PK, `payload`, `updated_at`, `deleted_at`).
  - `sync_changes`: Append-only change log (`sequence` autoincrement PK, `user_id`, `entity_type`, `entity_id`, `operation`, `version`, `changed_at`, indexed on `[user_id, sequence]`).
  - `sync_idempotency`: Client mutation deduplication ledger (`client_mutation_id` PK, `user_id`, `device_id`, `entity_type`, `entity_id`, `processed_at`), indexed on `processed_at` for retention pruning — nothing reads the ledger by time.
  - `shares`: Published StudyPackage snapshots (`id` PK `share_*`, `format`, `schema_version`, `title`, `description`, `author`, `access_type`, `passcode_hash`, `package_payload`, `user_id`, `view_count`, `download_count`, `expires_at`, `created_at`, `updated_at`).
- Migrations: schema is authored in `worker/src/schema.ts` (Drizzle ORM; config at root `drizzle.config.ts`). New migrations are generated with `npm run db:generate` (drizzle-kit) into `worker/migrations/` using the nested `NNNN_name/migration.sql` layout, matched via `migrations_pattern` in `wrangler.jsonc` — `wrangler d1 migrations create` is not used. Each migration directory also carries the `snapshot.json` baseline it was generated against, and those snapshots are what the next `db:generate` diffs from — commit them with the migration.
- **Idempotency-ledger retention: 30 days, pruned on the push path.** `sync_idempotency` is the one sync table that grows with traffic and is never otherwise reclaimed, so `core/retention.ts` retires entries older than `SYNC_IDEMPOTENCY_RETENTION_DAYS` (30) in bounded batches (`SYNC_IDEMPOTENCY_PRUNE_BATCH`, 500) served by `idx_sync_idempotency_processed_at`. The window must outlive the longest plausible replay delay, which is bounded by how long a client can hold an unsent mutation — its outbox drains whenever the app runs with connectivity — and the cutoff is generated in the same fixed-width ISO-8601 UTC text the ledger stores rather than through SQL date functions. **After expiry the ledger is not the only guard**, which is what makes expiring safe: a replayed `document` mutation fails its CAS or finds the row already present and returns a conflict, a replayed `highlight`/`drawing`/`flashcardReview` carries the timestamp the stored row holds and is rewritten with the same payload (one redundant `sync_changes` row, no data change), and a replayed `quizSession` finds its entity and is accepted without a second insert. Expiry therefore costs log noise and a conflict response, never duplicated data. Pruning rides `handleSyncPush` — the only traffic that can add rows — instead of a cron trigger, so there is no deployment configuration to keep in sync and an idle account's ledger stops growing rather than being swept. It runs only when the request processed at least one mutation, is bounded to one batch per push, and is best-effort: the mutations are already committed, so a prune failure is logged (`sync_idempotency prune failed:`) and never surfaces as a push error, while a pass that retires rows logs its count. `worker/src/core/__tests__/retention.test.ts` asserts the window floor, the bound, and the statement's semantics against real SQLite (`node:sqlite`, Node >= 22.5) — including that the plan uses the index — because a wrong prune here is a data-loss shape, not a performance one.

## Work Guidance

- Load the `wrangler` skill before running wrangler commands.
- Keep Worker dependencies minimal — Drizzle ORM is the allowed schema/query layer; avoid framework-level dependencies unless needed.
- Migration workflow: edit `worker/src/schema.ts` → `npm run db:generate` → `npm run db:apply:local` → verify → `npm run db:apply:remote` when ready. **Apply local first, remote later**; never edit a migration already applied on either side — fix forward with a new migration. **Remote is currently frozen by user decision (2026-09-18)** — pending migrations stack up there and applying them runs the legacy-table drop; see the PWA/Cloudflare section in the root `AGENTS.md` before touching `--remote` or `deploy:api`.
- **The AI model registry (`worker/src/core/aiModels.ts`) is the single source of truth for what `/api/ai/chat` can serve.** Adding, repricing, re-budgeting, or retiring a model is an edit there plus a `AI_CATALOG_VERSION` bump. Model facts must stay consistent with the client mirror (`src/domain/ai/services/aiModelCatalog.ts`), which the client cannot import and which is its offline fallback; bump the mirror's `AI_CATALOG_VERSION` in the same change or a cached client will keep metering against the old window. **`worker/src/core/__tests__/aiModelCatalog.coherence.test.ts` is the guard on that pair** — it is the only place that can see both the registry and the mirror, and it fails on any drift in ids, version, default, display, budgets, or prices; extend it when the catalog shape grows. A model whose provider is not wired yet must stay out of the servable path (it answers `PROVIDER_UNAVAILABLE`) rather than falling through to another model.
- **Availability is server-controlled and does not need a code change — use the right switch.** `AI_DISABLED_MODELS` (comma-separated catalog ids) retires individual models: each drops out of the served catalog and chat refuses it with `MODEL_UNAVAILABLE`. `AI_CHAT_DISABLED` (`true`/`1`/`yes`/`on`) is the **incident switch** and stops everything, default included, with `AI_DISABLED`; the catalog still answers 200 with `availability: 'disabled'` so clients can say "switched off" instead of "unreachable". Nothing is exempt from either switch — a per-model switch that spared the default could not actually take a broken provider out of rotation. The client refreshes from `GET /api/ai/models`, and its cached catalog expires after 24h (`WorkerAiModelCatalogRepository`, which never persists a disabled catalog), so a stale client cannot offer a retired model forever.
- **Every `/api/ai/chat` request writes exactly one structured telemetry record** (`worker/src/ai/telemetry.ts`, `logAiRequestTelemetry`), whatever it does: `{ event: 'ai.chat', status, model, provider, outcome, code?, stage?, reason?, message?, retryAfterSeconds?, firstEventMs?, durationMs, emittedTokenChunks, usage? }`. `outcome` is `ok` | `error` | `aborted` | `rejected`, and the level follows it — `error` logs at error (with `RATE_LIMITED` logged at warn to avoid alert fatigue on shared free endpoints), a policy refusal (`rejected`) warns, and a **cancellation logs at info on purpose**, because a user pressing Stop must not read as a fault or the failure rate becomes meaningless. `stage` captures the lifecycle phase (`pre-stream` or `mid-stream`); `reason` records the specific causal trigger (`client-abort`, `consumer-cancel`, `global-shutdown`, `model-disabled`, `model-unknown`, `provider-unconfigured`, `timeout`); `firstEventMs` and `durationMs` are the two numbers that make the 25s/45s deadlines auditable instead of assumed. **It must never carry prompt, document, or selection content** — ids, counts, durations, and normalized operational descriptions (or sanitized vendor text strictly capped at 256 chars) only; `worker/src/ai/__tests__/telemetry.test.ts` pins that by key and the route test asserts a grounded prompt's own markers never reach any log line. The record is logged as an **object, not a stringified line**, because Workers Logs indexes a logged object's fields — that is what makes "how often is MAX rate-limited" a filter rather than a text search. Records are written once per request via a guard in `handleAiChat`, so a path that fails and then unwinds cannot report twice.
- **Adding a provider means one file plus one registry row.** Implement `AiProvider` in `worker/src/ai/` (yield normalized `token`/`usage` events, throw `AiProviderError`, honor `AiProviderRequest.signal` and `connectTimeoutMs` for whichever part of the request the provider can cancel — and release the outbound request when the signal aborts, including from inside a `finally` so `iterator.return()` unwinds it), add it to `resolveAiProvider`, and point a catalog row at it. Never let vendor vocabulary reach `routes/ai.ts`: the route composes the prompt, pulls one event before committing to a 200 (so pre-stream failures keep their own status and code), frames SSE, and emits the terminal `done` with the catalog id. **A provider must never leave a pull unsettled** — the route's deadlines are the backstop, not the mechanism.
- **The Swift endpoint (MAX) is free, keyless, and rate-limited by IP.** `https://ukisai.com/api/swift/v1` allows roughly **5 prompts/minute per IP**, and every user of a deployment shares one Worker egress IP — so a 429 is normal traffic, not a fault: it is surfaced as `RATE_LIMITED` with `retryAfterSeconds` (parsed from the provider's "Try again in Ns."), and the client holds a courtesy cooldown. Two provider-specific requirements: `chat_template_kwargs.enable_thinking: false` (Qwen3 thinking otherwise consumes `max_tokens` before the answer and can return empty content) and `stream_options.include_usage` for token accounting. `reasoning_content` chunks are parsed and **discarded** — a provider-side default change degrades into ignored text, never leaked reasoning. `UKISAI_BASE_URL` overrides the base URL for local dev and tests.
- **The AI endpoint always sends a `system` message, so any model it names must support a system role.** That message carries the mode framing, the study material, and the selection — effectively all of the grounding. Gemma bases are unusable here: Google's prompt-structure docs state the system role "is not supported", and Cloudflare's runtime drops it **silently** rather than erroring, so the model returns a fluent answer with no knowledge of the material. The tell is the reported token usage — a grounded prompt is in the thousands of tokens, a dropped system message in the tens. Llama and Mistral chat formats have a real system slot; verify with a single request after any model change.
- **The `-lora` bases are not a usable substitute for this endpoint**, despite being the only models with windows below 24k. Both were tried: `@cf/google/gemma-7b-it-lora` (3,500) has no system role at all, and `@cf/meta-llama/llama-2-7b-chat-hf-lora` (8,192) responds but emits incoherent multilingual noise without an adapter bound. Do not swap them in to make the context ceiling easier to reach.
- Validate with `npx wrangler deploy --dry-run` before deploying.
- Local dev: `npm run dev:api` (`wrangler dev`) simulates D1 locally unless `--remote` is passed.
