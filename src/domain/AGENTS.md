# src/domain/ — Business Domain Models

## Purpose

Pure business domain models and logic — interfaces, types, and pure functions that describe the problem space. Domain modules must have zero React or UI dependencies.

## Ownership

Reserved domains:
- `reader/` — Document reading models, `DocumentRepository` and `AnnotationRepository` async contract interfaces, pure `parseAssetReference` (`utils/assetReference.ts` — syntax-only `lc-asset://{assetId}` extraction: returns the asset id, `undefined` for every other source; never queries storage and never sees `materialId`), `DocumentContentRepository` + `ImportedDocumentContent` (locally imported document markdown keyed by `documentId` — the explicit local representation of an imported material's content, distinct from the SW network cache), `DocumentNotFoundError` typed domain error, annotation value types (`annotation.types.ts`: `HighlightItem`, `DrawingPath`, `Point`, `HighlightColor`, `AnnotationMode`, `DrawingTool`)
- `quiz/` — Assessment engine: question models (5 types: `multiple_choice`, `multiple_select`, `true_false`, `identification`, `fill_in_blank`), quiz/session models, `virtualQuiz.ts` in-memory factory & deterministic question ordering, `QuestionRepository`/`QuizRepository`/`QuizSessionRepository` contracts (supporting multi-item/batch lookups, discriminated `CreateSessionInput`, and `getAllCompletedSessions` queries), strategy-pattern grading (`QuestionStrategy` + 5 implementations + `QuestionStrategyResolver`), pure `AssessmentService`, and pure tag helpers (`tags.ts` — `splitTagInput`/`tagKey`/`normalizeTags`/`mergeTags`: comma tokenization + case-preserving dedup normalization; the single source of truth applied at every tag write boundary and shared `TagInput`). (Note: the presentation badge palette lives in `features/quiz-management/utils/quizBadgeAppearance.ts`).
- `library/` — Document/library models, `LibraryRepository` async contract interface with DTOs (`CreateMaterialInput`, `UpdateMaterialInput`) — `StudyMaterial` carries portable content `tags?: string[]` (optional in both DTOs) — and `LibraryImportService` application service contract for atomic single/batch import and removal of material rows (`importMaterial`, `importMaterialBatch`, `removeMaterial` across material/questions/quizzes/document content, the material's `collectionMaterials` junction rows, **and the material's `localAssets` rows** — removal must not strand blobs or stale collection membership)
- `assets/` — Local binary asset access: `StoredAsset` (canonical row: `assetId`, `materialId`, `blob`, `mimeType`, `filename`, `importedAt`) and the read-only `AssetRepository` port (`get(assetId)`, `getByMaterialId(materialId)`). Source-agnostic by design — an asset is a material asset whether it arrived from an `.lcpack` clone, a PDF/image import, or a future importer.
- `flashcards/` — Spaced repetition domain: `Flashcard` domain mapping derived from `Question` (`questionToCard`), pure SM-2 scheduler (`review`, `isDue`, `createInitialReviewState`), deck ordering (`orderDeck`), and `FlashcardReviewRepository` async contract interface (supporting `getByKeys`, `getByMaterial`, and `getAllReviews`)
- `analytics/` — Pure learning analytics engine: canonical view types (`analytics.types.ts`), local timezone calendar date utilities (`dateUtils.ts`), pure consecutive streak calculation with grace evaluation (`streakEngine.ts`), 365-day volume activity calendar generator (`activityEngine.ts`), topic mastery scoring with difficulty multipliers ($1.0, 1.5, 2.0$) and deterministic tie-breaking (`masteryEngine.ts`), mutually exclusive card maturity partition and review forecast (`retentionEngine.ts`), and global study overview metrics aggregation (`overviewEngine.ts`)
- `ai/` — AI Tutor and study assistant domain: canonical message & thread types (`ai.types.ts`: `AiChatMessage`, `AiChatRequest`, `AiGenerationRequest`, `AiStructuredOutputValidator<T>`, `AiGenerationError`, `AiStreamEvent`, `AiTutorMode`, `AiUsage`, `AiThread`, `AiMessageRecord`, `AiMessageStatus`), pure markdown context extraction (`extractSectionContext.ts` bounding prompt tokens to headings/selections), pure context assembly (`AiContextBuilder.ts` bounding document and selection character limits and sanitizing prompts), the **model catalog** (`services/aiModelCatalog.ts` — the client's bundled mirror of the Worker's public registry: `AiModelDescriptor` (id, display, window, output reservation, document budget, `pricing: null` when free), `DEFAULT_AI_MODEL_CATALOG` as the offline fallback, pure `findAiModelDescriptor` / `getAiModelDescriptor` resolving by catalog id **or** the provider model id older turns recorded, `compareAiCatalogVersions` (numeric field-by-field ordering of the `YYYY-MM-DD.N` label; a malformed label can never outrank a well-formed one), `isAiCatalogVersion` (the format contract, asserted for both sides by the Worker's coherence test), `isAiModelCatalog`, and `getAiModelDescriptor`; the mirror is kept in lockstep with the registry by `worker/src/core/__tests__/aiModelCatalog.coherence.test.ts`, and `version` ranks only cache-vs-mirror — a served catalog always wins), published-rate cost estimation (`services/aiModelPricing.ts` — `estimateAiCostUsd` prices against the catalog descriptor's rates, returning `null` for an unknown or free model rather than a wrong charge), context-window budgeting (`services/aiContextBudget.ts` — pure `estimateContextUsage(counts, model?)` metered against a model's own window minus its output reservation, with the model-blind constants now just the catalog default's copy), provider-agnostic capability port (`AiService.ts`: `streamChat()`, `generateStructured()` — `AiChatRequest.model`/`AiGenerationRequest.model` carry an app-facing catalog id, never a provider), the read-only model catalog port (`repositories/AiModelCatalogRepository.ts` — the app's best-known catalog, answered offline from cache/bundle), and local thread persistence port (`AiChatRepository.ts` — local-only persistence contract: sessions scoped to a material (`AiThread.materialId`), newest-session resolution, orphan recovery via `recoverInterruptedMessages`, and cascade deletion of a session's messages; `AiThread` carries no mode, and `AiTutorMode` survives only as the server-side prompt selector on `AiChatRequest`)
- `generator/` — AI content generation domain models and pure validators (`generator.types.ts`, `questionDraftValidation.ts`): structured question and flashcard drafts, strict question payload validation across all 5 quiz types, atomic flashcard definitions, and provenance metadata mapping (`ai-generated`, `sec:...`)
- `importer/` — Content import domain: provider-agnostic ports (`ContentImporter`, `ImporterRegistry`, `ExtractionOptions`, `ImportAssetRepository`), domain types (`importer.types.ts`: `ExtractionResult`, `PageExtraction`, `ExtractionStats`, `ExtractionProgress`, `ImportMetadata`, `ImportCandidate`, `ImportSession`, `ImportError`, `ImportErrorCode`), and pure multi-pass markdown conversion pipeline (`markdownConverter/`: normalization, structure, page anchors, lists, tables, cleanup).
- `package/` — Portable study bundle domain: `StudyPackage` specification, pure schema and graph validator (`validateStudyPackage`), collision-free ID remapping engine (`remapStudyPackage`), package inspection engine (`inspectStudyPackage`), `StudyPackageSerializer` (pure JSON, Blob, and Base64 packaging serialization), and `StudyPackageImportService` application service port.
- `sync/` — Pure cloud synchronization domain: primitive types (`SyncEntityType`, `SyncOperation`, `SyncStatus`, `EntityVersion`, `SyncCursor`, `SessionCredentials`, `SyncMutation`, `SyncQueueItem`, `SyncState`, `ConflictDraft`, `ReconcileResult`, `SyncPushRequest`, `SyncPushResponse`, `SyncPullResponse`), strategy categorization (`SyncModel` + `getSyncModelForEntity`), monotonic cursor mathematics & validation (`isValidSyncCursor`, `assertCursorMonotonic`, `advanceSyncCursor`), composite sync identity (`createSyncStateKey`, `isValidSyncIdentity`), typed sync payloads (`DocumentSyncPayload`, `HighlightSyncPayload`, `DrawingSyncPayload`, `FlashcardReviewSyncPayload`, `QuizSessionSyncPayload`, `SyncPayloadMap`, `TypedSyncMutation`), optimistic concurrency & LWW resolution (`evaluateDocumentConcurrency`, `nextEntityVersion`, `compareLwwTimestamps`, `compareFlashcardReviews`), transport port contracts and DTOs (`SyncTransport`, `SyncPushRequest`, `SyncPushResponse`, `SyncPullResponse`), session credentials port (`SessionCredentialsProvider`), exponential backoff retry policies (`SyncRetryPolicy`, `calculateRetryDelay`), typed domain errors (`SyncError`, `SyncNetworkError`, `SyncHttpError`, `SyncProtocolError`, `SyncConflictError`, `OptimisticConcurrencyError`, `InvalidSyncPayloadError`, `InvalidSyncCursorError`, `OutboxTransactionError`), repository contracts (`SyncQueueRepository`, `SyncStateRepository`, `ConflictDraftRepository` with `resolveConflict`), and reconciliation port (`SyncReconciler`).
- `collections/` — Playlist-model grouping: `Collection` entity with `CreateCollectionInput`/`UpdateCollectionInput` DTOs (`models/Collection.ts`), `CollectionMaterial` M:N junction with per-collection ordering (`models/CollectionMaterial.ts`), and async repository contracts (`CollectionRepository` with `getAll`/`getById`/`create`/`update`/`delete`/`reorder`; `CollectionMaterialRepository` with `getByCollectionId`/`getByMaterialId`/`add`/`remove`/`reorder`/`removeByCollectionId`/`removeByMaterialId`).


## Local Contracts

- Zero React or UI dependencies. Domain modules import only from other domains or pure TypeScript libraries.
- Importable by any feature, application, or infrastructure layer.
- Domain logic must be testable without a browser environment.
- Analytics engines must never mutate their input arrays or domain objects.
- All timestamps in storage remain UTC ISO 8601 strings; date-key aggregations parse timestamps as instants and map to local calendar dates via `dateUtils.toLocalDateKey()`. Due comparisons use timestamp instants (`dueAt <= referenceDate`) before forecast grouping.
- Historical quiz attribution is derived strictly from immutable `questionSnapshots` on `QuizSession`, never from mutable question records.
- `CardMaturityBreakdown` strictly partitions cards into mutually exclusive buckets (`new`, `learning`, `review`, `mastered`) satisfying `newCount + learningCount + reviewCount + masteredCount === totalCards`.
- Global quiz accuracy is question-weighted (`totalCorrectAnswers / totalAnsweredQuestions * 100`).
- Topic mastery counts total answer attempts (`attemptCount`), not unique questions. Status includes `unattempted`, `needs_practice`, `proficient`, `mastered` (mastered requires $\ge 85\%$ weighted score AND $\ge 3$ attempts).
- `LibraryRepository` is the async contract (interface) that infrastructure implementations (e.g., `DexieLibraryRepository`) must satisfy. It deliberately declares **no delete**: `LibraryImportService.removeMaterial` is the single removal contract, so no caller can delete a material row without clearing its questions, quizzes, document content, collection membership, and stored assets — and since a material's dependencies can be acquired after creation, a cheaper row-only delete is never safe.
- `AssetRepository` is the async read-only contract for locally stored binary assets: `get(assetId)` resolves one asset by the identity a document reference carries, `getByMaterialId(materialId)` returns every asset grouped under a material (implemented by `DexieAssetRepository`). Read-only is a **contract** property, not a naming one: ports keep the repo-wide `*Repository` suffix (adapters `Dexie*Repository`) and the two-method surface is what keeps this one write-free. **`assetId` is identity — exactly one blob per id; `materialId` is only the grouping index and never identifies an individual asset.** `AssetRepository` must stay minimal (no `.lcpack`, remapping, `pkg_asset_*`, or import-session concepts) and write-free: asset writes belong to the persistence paths that own them, so the reader never becomes a second persistence boundary. The importer's `ImportAssetRepository` remains the single-asset **write-only** contract (`put`; one original PDF/image per material, written as `assetId = materialId`) — asset deletion belongs to the removal transaction that owns it (`DexieLibraryImportService.removeMaterial`), not to a port.
- `DocumentRepository` is the async contract for resolving `StudyMaterial` → `Document` (implemented by `HybridDocumentRepository` in `src/infrastructure/storage/repositories/`).
- `AnnotationRepository` is the async contract for highlight/drawing persistence keyed by `documentId` (implemented by `DexieAnnotationRepository`).
- `QuestionRepository`, `QuizRepository`, `QuizSessionRepository`, `FlashcardReviewRepository` are async contracts for persistence (implemented by Dexie repositories in `src/infrastructure/database/repositories/`).
- `SyncQueueRepository`, `SyncStateRepository`, `ConflictDraftRepository` are async contracts for persistence of cloud sync mutations, checkpoint cursors, and branched conflict drafts.
- `CollectionRepository`, `CollectionMaterialRepository` are async contracts for playlist-model collection persistence (implemented by Dexie repositories in `src/infrastructure/database/repositories/`).
- `SyncTransport` is the domain port contract for HTTP sync transport pushing mutations and pulling change deltas.
- All sync payloads, version numbers, and cursors enforce strict pure-domain invariants: cursors are monotonically increasing non-negative integers; documents use Model C optimistic concurrency with conflict draft branching; highlights, drawings, and flashcards follow Model A deterministic LWW semantics; quiz sessions follow Model B append-only semantics.

- `AssessmentService` is a pure domain service with zero persistence dependencies — validates, grades, and computes `QuizResult`/`QuizScore` via strategy dispatch.
- Tag casing policy (case-preserving display): stored tags keep the FIRST casing seen (`iOS` displays as `iOS`); `tagKey` (lowercase) is the derived canonical key for dedup/comparison and is never persisted. `normalizeTags` is the write-boundary normalization every tag write must pass through (repositories, editor service, migration) — question tags AND `StudyMaterial.tags` alike. Tags describe what content is about, live directly on the entity (no foreign keys), and are portable across `.lcpack` packages and cloud shares.
- `virtualQuiz.ts` generates derived, in-memory Virtual Quiz domain objects (`virtual:quizzes:...`) without mutating database state.

## Work Guidance

- **Uniform Domain Organization (ADR-013)**: Domain code is strictly organized into authorized responsibility subdirectories (`models/`, `repositories/`, `services/`, `engines/`, `context/`, `strategies/`, `reconcilers/`, `validation/`, `policies/`, `factories/`, `errors/`, `utils/`).
- **Domain Barrels Prohibited (ADR-010 / ADR-013)**: No `index.ts` barrel files are permitted in `src/domain/`. All consumers import directly from concrete module paths.
- **Primary Unit Test Discoverability & Colocation (ADR-012)**: Every testable domain behavior unit possesses a dedicated primary unit-test file named after the unit (`<UnitName>.ts` $\leftrightarrow$ `__tests__/<UnitName>.test.ts`), colocated within a `__tests__/` directory inside the specific responsibility folder where the tested unit resides.
- Domain tests must be 100% pure, deterministic unit tests with zero mocks (`vi.fn()`) — instantiate real classes and test observable input/output contracts.
- Spaced repetition, due dates, and timestamp comparisons must always supply a fixed reference instant (e.g. `new Date('2026-09-01T12:00:00.000Z')`), never non-deterministic `new Date()`.
