# src/app/screens/ — Application Screen & Route Composition Layer

## Purpose

Owns the route-level presentation screens, page layouts, and cross-feature capability compositions for Project LunaClair (ADR-014). Screens compose feature presentation components, feature hooks, and domain use cases into cohesive application pages.

## Ownership

- `home/` — Home Dashboard Screen:
  - `HomeScreen.tsx` — Dashboard route (`/`) answering "what should I do next?": a continue-studying hero (most recently opened material), a streak / due-today / accuracy stat strip from `useGlobalAnalytics`, a Recent shelf, and quick actions (New Material, Import a PDF, Explore packages, Browse library). Hero and shelves are suppressed entirely on a fresh install, which shows the empty-library state instead — that state also offers "Import a PDF", because Import has no nav slot and quick actions require a non-empty library. Import is otherwise reachable only from these Home affordances. `styles/home.stylex.ts` holds its StyleX rules; `hooks/useRecentMaterials.ts` holds the hero + recent-shelf recency model and `hooks/useHomeStats.ts` the stat-strip numbers + visibility gate.
- `library/` — Library Screen:
  - `LibraryScreen.tsx` — Route (`/library`) answering "what do I have?": an `Overview | Collections | Materials` switcher (URL `?view=`, default `overview`) over a capped overview (Collections shelf + materials with independent 6 → 12 → 25 steppers; the `View all` tab jump only appears past 25, smaller lists expand fully in place), a full collections browser (shelf + collection search + no-match empty state), and the full `LibraryView` section. The membership lens (`All` / `In a collection` / `Not in a collection`) is URL state: `filter` comes in as a prop and changes are reported via `onFilterChange` (the shell normalizes `all` to `undefined`). Membership resolves through `useAssignedMaterialIds`, whose `Set` answers both the `collected` and `uncollected` predicates. Tag pills are faceted: `search + membership` scope the ranked row (selected tags excluded from the derivation, pinned when missing). The switcher hides on an empty library; `styles/libraryScreen.stylex.ts` holds its StyleX rules; `components/PreviewStepper.tsx`, `components/LibraryViewSwitcher.tsx`, `components/LibraryCollectionsSection.tsx`, `components/LibraryMaterialsSection.tsx`, `utils/overviewSteps.ts`, `hooks/useLibraryData.ts` (`rankTags`, `useRankedTags`, `useBaseMaterials`, `useFacetedTags`, `useTagFilteredMaterials`, `useFilteredMaterials`, `useVisibleCollections`, `formatLibraryDescription`, `shouldShowViewSwitcher`), and `hooks/useLibraryModals.ts` (dialog state + save/close callbacks) hold the extracted chrome, queries, and dialogs so the screen stays a composer.
  - `modals/LibraryModals.tsx` — Composed dialog container for material creation/edit/delete plus collection creation. Material-to-collection assignment is deliberately absent — `MaterialCard`'s inline collections popover owns that action.
- `material-workspace/` — Material Workspace Screen:
  - `MaterialWorkspaceScreen.tsx` — Material workspace route (`/materials/:materialId?tab=&from=`) with Read, Write, Quiz, Flashcards, and Manage tabs. Breadcrumbs are origin-aware: `?from={collectionId}` (route `fromCollectionId`) resolves through `useCollection` and renders `Library / {collection} / {material}` with the collection crumb linking back to the playlist, degrading to `Library / {material}` when there is no origin or the origin collection no longer resolves (deleted, or a stale link) — provenance, never a membership claim. Tab changes and the auto-route-to-`write` redirect re-emit `fromCollectionId`, so the origin is not dropped mid-session.
  - `utils/workspaceBreadcrumbs.ts` — Pure breadcrumb derivation (`workspaceBreadcrumbs(materialTitle, origin)`) returning label + target pairs; the screen only supplies data and navigation. Unit-tested in `utils/__tests__/workspaceBreadcrumbs.test.ts`.
- `explore/` — Explore Hub Screen:
  - `ExploreScreen.tsx` — Content discovery route (`/explore`), shares-only: one unified card list of published `.lcpack` shares (verified/community badge, exact `originShareId` clone identity, 1-click cloning). No catalog section and no source filter; `onOpenMaterial` remains an optional no-op-compatible prop for route wiring.
- `quiz-session/` — Quiz Session Runner Screen:
  - `QuizSessionScreen.tsx` — Active quiz taking route (`/quiz/session/:id`) hosting the live quiz evaluation runner.
- `quiz-canvas/` — Quiz Canvas Builder Screen:
  - `QuizCanvasBuilderScreen.tsx` — Thin routing wrapper hosting the interactive quiz authoring canvas.
- `analytics/` — Learning Analytics Screen:
  - `AnalyticsScreen.tsx` — Learning insights and study statistics dashboard route (`/analytics`).
- `importer/` — Document Importer Screen:
  - `ImporterScreen.tsx` — 5-step document import wizard route (`/importer`).
- `shared-package/` — Shared Package Screen:
  - `SharedPackageScreen.tsx` — Cloud package inspection and import route (`/share/:shareId`, `/s/:code`).
- `collection-workspace/` — Collection Workspace Screen:
  - `CollectionWorkspaceScreen.tsx` — Playlist collection route (`/collections/:collectionId`) with `CollectionHero` (inline-editable title/description wired to `useUpdateCollection`, stats row, Quick Study over all tree quizzes via `onStartQuiz`, Edit/Delete actions), `CollectionMaterialList`, `AddMaterialsDrawer`, and a Quizzes tab with `CollectionQuizExplorer` (floating glass action bar with single/unified practice launch). Two `ConfirmationDialog`s live here: collection delete, and per-material removal — a row's remove control only records `pendingRemovalId`, and the click that confirms it fires `useRemoveMaterialFromCollection` (no material is ever removed off a single click). The Quizzes tab is nav-aware through `useFocusMode`, so tests that render this screen must wrap it in `FocusModeProvider` (in the app the provider comes from `AppShell`).
  - `components/CollectionMaterialList.tsx` — Thin composer for the playlist list view: mirrors the `materials` prop into optimistic local order (render-phase adjustment, so it survives re-fetches) and renders `CollectionMaterialRow` per material plus the hold-to-drag progress-ring SVG.
  - `components/CollectionMaterialRow.tsx` — One playlist row: drag handle, step number, open-title `<button>`, tag pills, mastery bar, and up/down/remove controls (the remove control is confirmation-gated by the screen, so its handler only requests removal). Tags render through the shared `Chip variant="neutral"` — the same pill vocabulary as `MaterialCard` / `CollectionQuizExplorer`; do not reintroduce a row-local tag text style. `data-material-id` and `data-drag-handle="true"` are the DOM contract the reorder hook queries. Responsive reductions: drag handle hidden `< 640px`, step numbering and mastery bar hidden `< 1024px`, arrows stacked vertically `< 640px`.
  - `components/CollectionHero.tsx` & `styles/collectionHero.stylex.ts` — Collection hero band: tinted background derived from the collection's own `color`, inline-editable title/description wired to `useUpdateCollection`, the stats row, Quick Study, Add Materials, and Edit/Delete affordances. Internal `CollectionIconButton` (icon tile + hover blur overlay + keyboard-only focus badge) and `CollectionStats` subcomponents hold the extracted branches; `styles/collectionHero.stylex.ts` holds the StyleX rules (project `*.stylex.ts` convention).
  - `hooks/useInlineEditDraft.ts` — Inline-editable field state: local draft seeded from a server value, committed on blur, Enter commits, Escape reverts, and a `resetKey` change re-seeds during render (guarded render-phase adjustment, so in-progress edits survive refetches returning identical server values). `onCommit` may return `false` to reject the draft and restore the server value — that is how an all-whitespace title is refused. Deduplicates the pattern shared with `EditCollectionModal`.
  - `hooks/useCollectionMaterialReorder.ts` — **Thin orchestrator** over the split reorder modules below (Sep 2026): owns the DOM-contract refs (`listRef` / `holdRingRef` / `holdCircleRef`), the live `items` mirror, `moveItem`, and the optimistic commit both gesture paths call, surfacing that API to `CollectionMaterialList`. The order mutation commits through `onReorder` (`useReorderCollectionMaterials`).
  - `utils/reorderListGeometry.ts` — Gesture-agnostic list geometry and commit animation shared by both drag paths: `ROW_GAP` / `SLOT_HYSTERESIS_PX`, `measureRows`, `findRow`, `candidateForCenter` (15px slot hysteresis, subpixel-antialiasing flicker elimination), `displaceSiblings` (real-time sibling gap opening), `clearDragProps`, and `settleRow` (smooth landing snap, then the commit hand-off), and `DRAG_LIFT_SHADOW` (one shared drag-lift shadow for both gesture paths — deliberately not a theme token, since GSAP animates the property and cannot interpolate a `var()`). Unit-tested in `utils/__tests__/reorderListGeometry.test.ts`, which also documents that the hysteresis band is inert at production row heights.
  - `hooks/useDesktopRowDrag.ts` — The `>= 640px` path: GSAP `Draggable` instances bound to the visible grip handle (`[data-drag-handle="true"]`), keyed per material and pruned when a material leaves the list. Instances outlive effect runs, so callbacks are read through refs and torn down once on unmount.
  - `hooks/useHoldToDragArming.ts` — The `< 640px` path: a 280ms hold arms a **manual pointer-capture drag** instead of `Draggable.startDrag` — a programmatic start from the stale press leaves GSAP listening for the wrong move events (touch-only for a mouse, scroll-claimed for touch) so the card never follows — with a circular progress ring centered at the touch point, row border illumination, and a non-passive `touchmove` scroll lock while armed. Also owns the teardown of every row listener and in-flight hold timer it registers. Its hold timer is a rule-documented `react-doctor/effect-needs-cleanup` false positive (the timer is created inside the `pointerdown` handler the effect only defines and attaches), suppressed in `doctor.config.ts` via a scoped `ignore.overrides` entry — do not "fix" it by adding top-level timer wrapping. See `.react-doctor/false-positives.md`, including the note that a **full** scan is required to surface this diagnostic on a newly added file.
  - `styles/collectionMaterialList.stylex.ts` — StyleX rules shared by the list and its row (project `*.stylex.ts` convention).
  - `styles/addMaterialsDrawer.stylex.ts` — StyleX rules for the add-materials slide-over and its rows, including the UA dialog-default overrides that keep the panel geometrically identical to the previous `role="dialog"` markup (project `*.stylex.ts` convention).
  - `utils/materialSearch.ts` — Pure `matchesSearch(material, term)` predicate for the drawer search (title/tag substring; `term` arrives already lower-cased so it is computed once per render rather than per row). Unit-tested in `utils/__tests__/materialSearch.test.ts`.
  - `modals/AddMaterialsDrawer.tsx` — Library search-and-add slide-over rendered as a **native modal `<dialog>`** (`showModal()`) portalled to `document.body`, anchored to the right edge with a blurred `::backdrop`. Search uses the shared `Input` (`startIcon` + `clearable`) like Library/Explore/QuizExplorer so styling stays consistent. Modal plumbing comes from the shared `useModalDialog` hook: open promotion, body scroll lock (so the main-page scrollbar hides), backdrop dismissal bound imperatively to the dialog element, and a document-level Escape `keydown` fallback for a non-modal render where `cancel` never fires. The hook reads its callbacks through Effect Events so no dismissal listener re-subscribes on parent redraws; the drawer keeps its own `cancel` semantics in JSX and is mounted only while open. `MaterialPickerRow` holds the extracted row (icon mark, title, up to two tags as shared `Chip variant="neutral"` pills — same tag vocabulary as `CollectionMaterialRow` / `MaterialCard` — and an Add/Added button), and its search predicate is the pure `matchesSearch`. The style block deliberately overrides the UA dialog defaults — `height: auto` (so the `top`/`bottom` pair keeps the full-viewport-height stretch instead of collapsing to the UA `fit-content`), `overflow: visible`, zero padding, zero padding-side borders, and `max-height: none` — so the panel stays geometrically identical to the previous `role="dialog"` markup. Reports added materials through `onMaterialAdded`.

## Local Contracts

- **Screen Layer Exclusivity (ADR-014)**: Features must never own route screens; all route screens live here.
- **Cross-Feature Composition**: When an interaction requires multiple domain capabilities (e.g. collection workspace coordinating collections and materials), the composition occurs in this screen layer.
- Screens consume features strictly via direct module paths (ADR-010). Features must not import from `src/app/screens/`.
- **Folder taxonomy (Sep 2026)**: a screen folder exposes exactly one route screen (`*Screen.tsx`) at its root. Everything else lives in a feature-style subfolder — `components/` (screen-local chrome), `modals/` (dialogs), `hooks/` (state and gesture hooks), `utils/` (pure helpers), `styles/` (`*.stylex.ts`) — with tests colocated in the matching `__tests__/` (ADR-012). Screen folders whose screen needs none of these stay flat: `analytics/`, `explore/`, `importer/`, `quiz-canvas/`, `quiz-session/`, `shared-package/`.
