# src/app/screens/ — Application Screen & Route Composition Layer

## Purpose

Owns the route-level presentation screens, page layouts, and cross-feature capability compositions for Project LunaClair (ADR-014). Screens compose feature presentation components, feature hooks, and domain use cases into cohesive application pages.

## Ownership

- `home/` — Home Dashboard Screen:
  - `HomeScreen.tsx` — Dashboard route (`/`) answering "what should I do next?": a continue-studying hero (most recently opened material), a streak / due-today / accuracy stat strip from `useGlobalAnalytics`, a Recent shelf, and quick actions (New Material, Import a PDF, Explore packages, Browse library). Hero and shelves are suppressed entirely on a fresh install, which shows the empty-library state instead — that state also offers "Import a PDF", because Import has no nav slot and quick actions require a non-empty library. Import is otherwise reachable only from these Home affordances. `styles/home.stylex.ts` holds its StyleX rules; `hooks/useRecentMaterials.ts` holds the hero + recent-shelf recency model and `hooks/useHomeStats.ts` the stat-strip numbers + visibility gate.
- `library/` — Library Screen:
  - `LibraryScreen.tsx` — Route (`/library`) answering "what do I have?": an `Overview | Collections | Materials` switcher (URL `?view=`, default `overview`) over a capped overview (Collections shelf + materials with independent 6 → 12 → 25 steppers; the `View all` tab jump only appears past 25, smaller lists expand fully in place), a full collections browser (shelf + collection search + no-match empty state), and the full `LibraryView` section. The membership lens (`All` / `In a collection` / `Not in a collection`) is URL state: `filter` comes in as a prop and changes are reported via `onFilterChange` (the shell normalizes `all` to `undefined`). Membership resolves through `useAssignedMaterialIds`, whose `Set` answers both the `collected` and `uncollected` predicates. Tag pills are faceted: `search + membership` scope the ranked row (selected tags excluded from the derivation, pinned when missing). The switcher hides on an empty library; `styles/libraryScreen.stylex.ts` holds its StyleX rules; `components/PreviewStepper.tsx`, `components/LibraryViewSwitcher.tsx`, `components/LibraryCollectionsSection.tsx`, `components/LibraryMaterialsSection.tsx`, `utils/overviewSteps.ts`, `hooks/useLibraryData.ts` (`rankTags`, `useRankedTags`, `useBaseMaterials`, `useFacetedTags`, `useTagFilteredMaterials`, `useFilteredMaterials`, `useVisibleCollections`, `formatLibraryDescription`, `shouldShowViewSwitcher`), and `hooks/useLibraryModals.ts` (dialog state + save/close callbacks) hold the extracted chrome, queries, and dialogs so the screen stays a composer.
  - `modals/LibraryModals.tsx` — Composed dialog container for material creation/edit/removal plus collection creation (removal renders `features/materials` `RemoveMaterialModal`, which owns the consequence copy). Material-to-collection assignment is deliberately absent — `MaterialCard`'s inline collections popover owns that action.
- `material-workspace/` — Material Workspace Screen (`MaterialWorkspaceScreen.tsx`, composer over `components/` + `hooks/` + `utils/` + `styles/`):
  - `MaterialWorkspaceScreen.tsx` — Material workspace route (`/materials/:materialId?tab=&from=`) with two-tier navigation: a `WorkspaceModeSwitch` (Study vs Manage) over per-mode tab strips — Study hosts Read, Quiz, Flashcards (everyday surface), Manage hosts Document, Question Bank, Quiz Catalog, Attachments (back office). Tab keys are URL state owned by `routing.ts` (`MATERIAL_WORKSPACE_TABS`; mode derives via `workspaceModeOfTab`, never serialized); an unknown `?tab=` degrades to `read` there and in the screen, and the retired `?tab=manage` maps onto Question Bank (honoring a legacy `?section=quizzes`). Mode switches return to the mode's last-visited tab (`lastInMode`, render-phase synced so Back/Forward and deep links correct it). Breadcrumbs are origin-aware: `?from={collectionId}` (route `fromCollectionId`) resolves through `useCollection` and renders `Library / {collection} / {material}` with the collection crumb linking back to the playlist, degrading to `Library / {material}` when there is no origin or the origin collection no longer resolves (deleted, or a stale link) — provenance, never a membership claim. Tab changes re-emit `fromCollectionId`, so the origin is not dropped mid-session. Tabs are mount-once (`hooks/useVisitedTabs`): visited tabs stay mounted and hide when inactive, so writer drafts, live quiz answers, and flashcard sessions survive tab switches — including switches across modes. Exiting a finished quiz resets the embedded runner in place (stays on the Quiz tab) instead of leaving for the library. The header shows the material description plus tag `Chip`s with Source (conditional on a preserved original) / Share / Export / AI actions (icon-only under 640px); Share / Export live only here — the embedded tabs carry no material-level Share/Export of their own. An empty document stays on Read with its Start Writing CTA (no auto-redirect to Write). A missing material returns to the origin collection when `?from=` is present, else the library.
  - `hooks/useVisitedTabs.ts` — Mount-once tab memory (visited tabs in visit order, never forgotten); unit-tested in `hooks/__tests__/useVisitedTabs.test.ts`.
  - `hooks/useWorkspaceAssets.ts` — Workspace-owned stored-asset reads sharing the reader's `readerQueryKeys.assets(materialId)` cache key (one Dexie read serves figure resolution and the Attachments/Source surfaces).
  - `components/WorkspaceActions.tsx` — Material-level header actions (Source when an original exists, Share, Export as .lcpack, AI toggle; icon-only under 640px).
  - `components/WorkspaceModeSwitch.tsx` — Study/Manage mode switch (graduation-cap / clipboard-list; no icon repeats a tab icon, no counts — static tab counts carry no information).
  - `components/WorkspaceTabPanels.tsx` — Mount-once tab panels (branch-free composition over the `TabSlot` mount/hide helper); Question Bank / Quiz Catalog render as `QuizManagementScreen` sections, Attachments as `WorkspaceAttachments`.
  - `components/WorkspaceMetaTags.tsx` — Material tag row under the header (shared `Chip` vocabulary).
  - `components/WorkspaceNotFound.tsx` — Missing-material state (returns to the origin collection when `?from=` is present, else the library).
  - `components/WorkspaceAttachments.tsx` — Attachments tab: share-budget meter (`useStudyPackageSize` vs the 5 MiB guard), preserved-original card, referenced-figure list with Preview/Download. Read-only by design — per-asset deletion has no repository contract, so files leave only with the whole material (footnote says so).
  - `components/WorkspaceSourceDialog.tsx` — Preserved-file viewer (image direct, PDF via sandboxed `allow-same-origin` iframe on the blob URL — scripts stay blocked; always paired with download/open links for iOS, whose Safari won't render PDFs in iframes).
  - `styles/materialWorkspace.stylex.ts` — Workspace StyleX rules (loading, actions, tag row, tab scroll lane).
  - `utils/workspaceBreadcrumbs.ts` — Pure breadcrumb derivation (`workspaceBreadcrumbs(materialTitle, origin)`) returning label + target pairs; the screen only supplies data and navigation. Unit-tested in `utils/__tests__/workspaceBreadcrumbs.test.ts`.
  - `utils/formatBytes.ts` — Human file-size formatting for attachments; unit-tested in `utils/__tests__/formatBytes.test.ts`.
- `explore/` — Explore Hub Screen (composer over `components/` + `hooks/` + `utils/` + `styles/`, own + new tests in `__tests__/`):
  - `ExploreScreen.tsx` — Content discovery route (`/explore`), shares-only: one unified card list of published `.lcpack` shares (community/verified badge, exact `originShareId` clone identity, 1-click cloning). No catalog section and no source filter. `onOpenMaterial` is a **required** prop and opens a *local* material — it is the post-clone next step behind an `In My Library` card; non-imported shares are viewed through `onOpenShare` on their landing surface. Filters are **URL state** (`/explore?q=&sort=`, owned by the shell like `/library?filter=&view=`): the screen receives `q`/`sort` and reports committed changes through `onFiltersChange`, storing no filter state of its own. `isVerified` is currently unreachable in production (the shares API returns no such field), so the card renders `Community` for every share — see `docs/architecture/plans/explore-hub-overhaul-plan.md` §3.1 before asserting otherwise. Error state offers a `refetch` retry; empty-state copy comes from `utils/exploreFilters`. Above the grid a quiet count line reports what is actually rendered for the committed `q`/`sort` (`1 result` / `N results`) — deliberately the *page* count, since the hub fetches a single page (plan §3.2) — and is omitted entirely when the empty state is showing, so a query miss is never accompanied by a `0 results` line.
  - `components/ShareCard.tsx` — One share card (byline row, description, badges, `In My Library` pill, Clone action) with `styles/shareCard.stylex.ts`. Semantics: the title inside the `h3` is a real `<button>` and is the **only** open control — it carries the accessible name (the visible title text) and the `:focus-visible` ring, so one keyboard/AT path exists per action. A body click on the shell opens the share too, as a mouse affordance only, guarded by a `closest('button, a, input, textarea, select, [role="menu"], [role="dialog"]')` backstop (same shape as `MaterialCard`). Deliberately **no** `role="button"`/`tabIndex` on the shell — nested buttons inside a button role is invalid ARIA — and no second open button (the retired `View` action duplicated the title click). The shell's body-click handler is a rule-documented `react-doctor/no-static-element-interactions` false positive, scoped in `doctor.config.ts` (see `.react-doctor/false-positives.md`); do not "fix" it by adding a role. The footer action is state-dependent and never a dead end: `Clone to Library` while the share is absent from the library, then **Open in library** in the same footer slot once `item.libraryMaterialId` resolves — an `isInLibrary` card carries no disabled Clone button. The action is a native accent-pill `<button>` (disabled + `aria-busy` mid-clone), not a shared `Button`, matching `MaterialCard`'s Quiz action voice. The card's anatomy is deliberately `MaterialCard`'s (Sep 2026 unification): shared meter (`padding: 20` / `gap: 12`), single-line ellipsis title, 2-line reserved description — rendered unconditionally, showing an italic `--color-text-disabled` `No description provided` placeholder in its slot when the share has none — quiet `--color-text-disabled` meta voice, a **byline row** under the title — author left (`item.author ?? 'Community upload'`), download/view stats right as icon + bare number with the wording on the stat's `aria-label` — Community/Verified + `In My Library` pinned to a bottom badge row (`marginTop: auto`, `minHeight: 30`) so grid rows align, one right-aligned accent-pill action in a bordered-top footer (`minHeight: 45`), and a lift-only hover — no shadow; the border accent on `Card` through `xstyle` carries the hover, the same idiom as `MaterialCard`. Badge pills use `MaterialCard`'s `badgeButton` geometry with the per-instance inline color triple (bg/border on the hue's alpha, text in the full hue) — not the shared `Chip`, whose 9.5px type is the tag vocabulary, not the badge one. **StyleX gotcha (real defect this fixed):** a `border*` shorthand whose value contains `var()` or `color-mix()` is silently dropped by StyleX — the footer divider never rendered until `borderTop` was rewritten as the `borderTopWidth`/`borderTopStyle`/`borderTopColor` longhand triplet; write all `var()`-carrying borders longhand (same convention as `materialCard.stylex.ts`).
  - `components/ExploreFilterBar.tsx` & `styles/exploreFilterBar.stylex.ts` — Search `Input` + a shared `SegmentedControl` for sort (`radiogroup`, `label="Sort explore items"`, `size="sm"`); pure presentation, both values arrive as props and changes leave through callbacks. Sort deliberately uses the app's segmented vocabulary rather than a bespoke `<select>` — options stay visible, and arrow-key move-and-select comes from the component's own APG behavior. The control carries `flexShrink: 0` so the `flex: 1` search field absorbs the squeeze before the bar wraps.
  - `hooks/useExploreFilterDraft.ts` — Owns the **in-progress** query only. Typing debounces (250ms) into `onCommit` **from the change handler**, not from an effect: an effect pushing state to the parent also re-publishes a stale query after Back/Forward and fights the restored URL (that bug shipped briefly and was caught by the rewritten E2E). Re-seeds the draft on an external `q` change, cancels queued commits on unmount and on URL change, commits a cleared box as `undefined`, and switches sort immediately. Unit-tested in `hooks/__tests__/useExploreFilterDraft.test.ts`.
  - `utils/exploreFilters.ts` — `ExploreFilters` contract + pure `describeExploreEmptyState(q)` (a query miss is recoverable, an empty hub is not). Unit-tested in `utils/__tests__/exploreFilters.test.ts`.
  - `styles/exploreScreen.stylex.ts` — The result count line and the share grid.

- `shared-package/` — Shared Package Screen:
  - `SharedPackageScreen.tsx` — Cloud package inspection and import route (`/share/:shareId`, `/s/:code`). Provenance is URL state: `?from=` arrives as a parsed `AppRoute` prop and drives the first breadcrumb plus the Back wording (`Explore` / `Back to Explore` from the hub, else the `Library` default), while `onCancel` owns the actual navigation — the screen names the destination, the shell performs it. The trail ends with the **package's own name** once resolved (the `Library / {collection} / {material}` shape the workspace uses), falling back to the generic `Shared Package` only in the loading/passcode/error states that cannot know it yet; the title is resolved once and feeds both the page heading and the last crumb so they cannot disagree. Every render state (loading, passcode challenge, error, ready) resolves the same labels, so the crumb never flips mid-load. Clone state is **persistent, not session-local**: the screen derives membership through `useLocalOriginMaterials()` (`originShareId` → local material), so a share cloned earlier — here or on the Explore hub — is recognised on a fresh visit instead of looking un-cloned. It also surfaces the package's **material tags** (`summary.tags`, shared `Chip` pills) under the meta row, so what the clone will carry is visible before cloning — these tags come from the package itself, and an untagged package shows none. The primary action is therefore three-state: `Clone to Library` → (already known) **`Open in library`**, which jumps to the local material in the workspace; and, right after a clone *this* session, a disabled `Cloned to Library` while the success banner above it carries the open action (no duplicate control for one action). Its own clone path calls `importStudyPackage` with `originShareId: shareId` — that stamp is what makes the clone identifiable everywhere, and omitting it was a real defect (duplicate clones; the Explore card never lit up as `In My Library`).
- `collection-workspace/` — Collection Workspace Screen:
  - `CollectionWorkspaceScreen.tsx` — Playlist collection route (`/collections/:collectionId`) with `CollectionHero` (inline-editable title/description wired to `useUpdateCollection`, stats row, Quick Study over all tree quizzes via `onStartQuiz`, Edit/Delete actions), `CollectionMaterialList`, `AddMaterialsDrawer`, and a Quizzes tab with `CollectionQuizExplorer` (floating glass action bar with single/unified practice launch). Two `ConfirmationDialog`s live here: collection delete, and per-material removal — a row's remove control only records `pendingRemovalId`, and the click that confirms it fires `useRemoveMaterialFromCollection` (no material is ever removed off a single click). The Quizzes tab is nav-aware through `useFocusMode`, so tests that render this screen must wrap it in `FocusModeProvider` (in the app the provider comes from `AppShell`).
  - `components/CollectionMaterialList.tsx` — Thin composer for the playlist list view: mirrors the `materials` prop into optimistic local order (render-phase adjustment, so it survives re-fetches) and renders `CollectionMaterialRow` per material plus the hold-to-drag progress-ring SVG.
  - `components/CollectionMaterialRow.tsx` — One playlist row: drag handle, step number, open-title `<button>`, tag pills, mastery bar, and up/down/remove controls (the remove control is confirmation-gated by the screen, so its handler only requests removal). Tags render through the shared `Chip variant="neutral"` — the same pill vocabulary as `MaterialCard` / `CollectionQuizExplorer`; do not reintroduce a row-local tag text style. `data-material-id` and `data-drag-handle="true"` are the DOM contract the reorder hook queries. Responsive reductions: drag handle hidden `< 640px`, step numbering and mastery bar hidden `< 1024px`, arrows stacked vertically `< 640px`.
  - `components/CollectionHero.tsx` & `styles/collectionHero.stylex.ts` — Collection hero band: tinted background derived from the collection's own `color`, inline-editable title/description wired to `useUpdateCollection`, the stats row, Quick Study, Add Materials, and Edit/Delete affordances. Internal `CollectionIconButton` (icon tile + hover blur overlay + keyboard-only focus badge) and `CollectionStats` subcomponents hold the extracted branches; `styles/collectionHero.stylex.ts` holds the StyleX rules (project `*.stylex.ts` convention).
  - `hooks/useInlineEditDraft.ts` — Inline-editable field state: local draft seeded from a server value, committed on blur, Enter commits, Escape reverts, and a `resetKey` change re-seeds during render (guarded render-phase adjustment, so in-progress edits survive refetches returning identical server values). `onCommit` may return `false` to reject the draft and restore the server value — that is how an all-whitespace title is refused. Deduplicates the pattern shared with `EditCollectionModal`.
  - `hooks/useCollectionMaterialReorder.ts` — **Thin orchestrator** over the split reorder modules below (Sep 2026): owns the DOM-contract refs (`listRef` / `holdRingRef` / `holdCircleRef`), the live `items` mirror, `moveItem`, and the optimistic commit both gesture paths call, surfacing that API to `CollectionMaterialList`. The order mutation commits through `onReorder` (`useReorderCollectionMaterials`).
  - `utils/reorderListGeometry.ts` — Gesture-agnostic list geometry and commit animation shared by both drag paths: `ROW_GAP` / `SLOT_HYSTERESIS_PX`, `measureRows`, `findRow`, `candidateForCenter` (15px slot hysteresis, subpixel-antialiasing flicker elimination), `displaceSiblings` (real-time sibling gap opening), `clearDragProps`, and `settleRow` (smooth landing snap, then the commit hand-off), and `DRAG_LIFT_SHADOW` (one shared drag-lift shadow for both gesture paths — deliberately not a theme token, since GSAP animates the property and cannot interpolate a `var()`). Unit-tested in `utils/__tests__/reorderListGeometry.test.ts`, which also documents that the hysteresis band is inert at production row heights.
  - `hooks/useDesktopRowDrag.ts` — The `>= 640px` path: GSAP `Draggable` instances bound to the visible grip handle (`[data-drag-handle="true"]`), keyed per material and pruned when a material leaves the list. Instances outlive effect runs, so callbacks are read through refs and torn down once on unmount.
  - `hooks/useHoldToDragArming.ts` — The `< 640px` path: a 280ms hold arms a **manual pointer-capture drag** instead of `Draggable.startDrag` — a programmatic start from the stale press leaves GSAP listening for the wrong move events (touch-only for a mouse, scroll-claimed for touch) so the card never follows — with a circular progress ring centered at the touch point, row border illumination, and a non-passive `touchmove` scroll lock while armed. Also owns the teardown of every row listener and in-flight hold timer it registers. Its hold timer is a rule-documented `react-doctor/effect-needs-cleanup` false positive (the timer is created inside the `pointerdown` handler the effect only defines and attaches), suppressed in `doctor.config.ts` via a scoped `ignore.overrides` entry — do not "fix" it by adding top-level timer wrapping. See `.react-doctor/false-positives.md`, including the note that a **full** scan is required to surface this diagnostic on a newly added file.
  - `styles/collectionMaterialList.stylex.ts` — StyleX rules shared by the list and its row (project `*.stylex.ts` convention).
  - `styles/addMaterialsDrawer.stylex.ts` — StyleX rules for the add-materials slide-over and its rows, including the UA dialog-default overrides that keep the panel geometrically identical to the previous `role="dialog"` markup (project `*.stylex.ts` convention).
  - `utils/materialSearch.ts` — Pure `matchesSearch(material, term)` predicate for the drawer search (title/tag substring; `term` arrives already lower-cased so it is computed once per render rather than per row). Unit-tested in `utils/__tests__/materialSearch.test.ts`.
  - `modals/AddMaterialsDrawer.tsx` — Library search-and-add slide-over rendered as a **native modal `<dialog>`** (`showModal()`) portalled to `document.body`, anchored to the right edge with a blurred `::backdrop`. Search uses the shared `Input` (`startIcon` + `clearable`) like Library/Explore/QuizExplorer so styling stays consistent. Modal plumbing comes from the shared `useModalDialog` hook: open promotion, body scroll lock (so the main-page scrollbar hides), backdrop dismissal bound imperatively to the dialog element, and a document-level Escape `keydown` fallback for a non-modal render where `cancel` never fires. The hook reads its callbacks through Effect Events so no dismissal listener re-subscribes on parent redraws; the drawer keeps its own `cancel` semantics in JSX and is mounted only while open. `MaterialPickerRow` holds the extracted row (icon mark, title, up to two tags as shared `Chip variant="neutral"` pills — same tag vocabulary as `CollectionMaterialRow` / `MaterialCard` — and an Add/Added button), and its search predicate is the pure `matchesSearch`. The style block deliberately overrides the UA dialog defaults — `height: auto` (so the `top`/`bottom` pair keeps the full-viewport-height stretch instead of collapsing to the UA `fit-content`), `overflow: visible`, zero padding, zero padding-side borders, and `max-height: none` — so the panel stays geometrically identical to the previous `role="dialog"` markup. Reports added materials through `onMaterialAdded`.

## Local Contracts

- **Screen Layer Exclusivity (ADR-014)**: Features must never own route screens; all route screens live here.
- **Cross-Feature Composition**: When an interaction requires multiple domain capabilities (e.g. collection workspace coordinating collections and materials), the composition occurs in this screen layer.
- Screens consume features strictly via direct module paths (ADR-010). Features must not import from `src/app/screens/`.
- **Folder taxonomy (Sep 2026)**: a screen folder exposes exactly one route screen (`*Screen.tsx`) at its root. Everything else lives in a feature-style subfolder — `components/` (screen-local chrome), `modals/` (dialogs), `hooks/` (state and gesture hooks), `utils/` (pure helpers), `styles/` (`*.stylex.ts`) — with tests colocated in the matching `__tests__/` (ADR-012). Screen folders whose screen needs none of these stay flat: `analytics/`, `importer/`, `quiz-canvas/`, `quiz-session/`, `shared-package/`.
