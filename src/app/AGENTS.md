# src/app/ — Application Shell

## Purpose

Application-level orchestration: the root shell layout, configuration constants, and React providers. Owns the top-level rendering tree but contains no business logic.

## Ownership

- `layouts/AppShell.tsx` — Thin composition root (split from a single 700-line component): wires `useAppRoute` (route state/URL sync), `useShellFocusMode` (Focus Mode state + `Cmd/Ctrl+B` + persistence), the `useFocusModeMotion` GSAP rail/FAB animation, the `main` bottom-inset measurement (feeds the quiz canvas toolbar lane), and the `AppRoute` discriminated-union re-export (consumed by `AppSidebar`, `MaterialWorkspace`, and feature screens). Renders the rail (`AppSidebar`), `main` with `<ShellRoutes>`, the Focus Mode floating logo restore button, and the global overlays — `OfflineBanner`, `InstallPrompt` + `InstallInstructionsDialog` (gated off in dev via `import.meta.env.DEV`), and `OnboardingTutorial` (all suppressed on immersive quiz routes).
- `layouts/ShellRoutes.tsx` — Per-route screen renderer: renders the current `AppRoute`'s screen (Library / Available / Preview / Terms / Analytics / Subject / MaterialWorkspace / QuizCanvasBuilder / QuizScreen) and owns the navigation handlers the screens need (open material/subject, launch quiz, manage, exit). `AvailableMaterialsScreen` receives `onPreview` (navigate to `{ kind: 'preview' }`); the `preview` route renders `PreviewMaterialScreen` (read-only surface, back → Available, `onOpenMaterial` after Add-to-Library import); the `analytics` route renders `AnalyticsScreen`. Consumes `useTouchMaterial` and passes `bottomInset` (measured by `AppShell`) to `QuizCanvasBuilder`. The `quiz-canvas` route uses WINDOW-SCROLL mode (migrated off the internal scroller): the workspace grows to content and the DOCUMENT scrolls, exactly like every other route — `main` carries no route-scoped pin, and the toolbar lane's bottom-pin bound is `bottomInset`.
- `layouts/useAppRoute.ts` — `useAppRoute` hook: parses the URL on mount (`urlToRoute`), syncs the URL on every navigation (`pushState`), and follows browser back/forward (`popstate`); returns `{ currentRoute, navigate }`.
- `layouts/useShellFocusMode.ts` — `useShellFocusMode` hook: Focus Mode state (initialized from `STORAGE_KEYS.settings.focusMode`, persisted on every toggle) plus the global `Cmd/Ctrl+B` shortcut; returns `{ isFocusMode, toggleFocusMode }`.
- `layouts/MaterialWorkspace.tsx` — Material workspace shell (Read / Write / Quiz / Flashcards / Manage tab bar + Page shell) wrapping `ReaderScreen`, `MaterialWriterTab`, `QuizScreen`, `FlashcardScreen`, and `QuizManagementScreen`. Also owns the AI Study Assistant integration: manages `isAiOpen`, unread/streaming status indicators, global `Cmd/Ctrl+J` shortcut, section-aware selection actions from Reader, and hosts `<AiChatDrawer>` and `<AiDrawerToggleButton>`. Consumes catalog hooks (`useMaterial`, `useSubject`, `useTerm`) and embedded screens/drawers via direct imports (no-barrel-import exception, see `src/features/AGENTS.md`).

- `layouts/InstallPrompt.tsx` — PWA install surfaces: `InstallPrompt` (one-time **iOS-only** card, fixed bottom-center, `zIndex` 300 — shown from the second distinct browser session onward, dismissed forever via `STORAGE_KEYS.settings.installDismissed`, hidden when already installed, in dev builds, or on immersive quiz routes) and `InstallInstructionsDialog` (opt-in, platform-aware "how to install" dialog — iOS "Share → Add to Home Screen" steps vs. generic browser-install instructions).
- `layouts/OnboardingTutorial.tsx` — First-run welcome tutorial: a FULL-SCREEN takeover rendered as a native `<dialog>` via `showModal()` (focus trapping, Escape-to-close, and focus restoration for free; Escape maps to Skip through the `cancel` event — no manual keydown listener) — whole viewport becomes the onboarding screen: brand header + Skip, centered hero slide with per-step fade-up via `stylex.keyframes`, bottom action bar with progress dots + Back text button + full-width CTA. One-time and skippable, `zIndex` 1000 (below toasts), gated forever by `STORAGE_KEYS.settings.onboardingDone`, locks background scroll while open. 4 bundled slides (Welcome → Library → Terms & Quizzes → Finish). Deliberately NOT dev-gated (unlike install surfaces) — onboarding is a real product flow. Finish and Skip/Escape both call `useCases.library.syncDefaultTerms.execute()` (insert-if-missing into Dexie, failure-tolerant) and toast on success — dismissal is never punished; Finish shows a "Setting up…" state while awaiting, Skip is fire-and-forget. The tutorial itself never depends on the network — bundled app chrome.
- `layouts/installDetection.ts` — pure PWA detection helpers: `isIOS` (incl. the iPadOS 13+ MacIntel/maxTouchPoints heuristic) and `isStandalone` (`display-mode: standalone` + legacy `navigator.standalone`).
- `layouts/OfflineBanner.tsx` — Global connectivity status indicator (`zIndex: 200` — above Focus Mode FAB at 150, below toasts at 9999). Driven by `navigator.onLine` + `online`/`offline` events: while disconnected a persistent, draggable "Offline" pill stays on screen; auto-collapses to an icon-only circular badge (`32x32px`, `borderRadius: 9999`) after 4s of inactivity, expanding on hover; stays in its current collapsed/expanded size while dragging (no auto-expansion during movement); magnetically snaps to closest side border (`16px` left/right margin) on release; all box shadows (`boxShadow`) and borders live directly on the inner rounded pill/circle (`borderRadius: 9999`) with zero rectangular wrapper shadow artifacts; position persists in `localStorage` under the versioned key `lunaclair:settings:offline-banner-pos:v1`; on recovery a transient success-toned "You're back online" chip shows (~3s auto-hide). `aria-live="polite"`; purely informational — communicates connectivity state, while background queueing and convergence are managed by the Sync Engine.
- `layouts/AppSidebar/AppSidebar.tsx` — Global navigation rail (desktop sidebar, tablet rail, mobile bottom dock) with GSAP sliding active pill. Nav links: Library (`/`), Explore (`/explore` — Unified Explore Hub), Analytics/Insights (`/analytics`), Terms (`/terms`), Import (`/import`), plus subject/material context links. Also renders a quiet opt-in install row (`Install app` / `Add to Home Screen`, UA-branched copy) in the nav section — hidden when already installed (`isStandalone`) and on mobile, where the iOS one-time card serves mobile iOS. Navigation links (Library, Explore, Terms, Subjects) pin to the top padding (no brand header — brand identity lives only in the bottom-left footer). The footer is a brand card rendering `SyncStatusPill` alongside the Focus Mode trigger: row 1 = logo + full `Project LunaClair` title (never truncated) + `v0.2.0` badge; row 2 = `Focus Mode (Cmd+B)` label + Focus icon; stripped of its own border/background on tablet so it sits cleanly inside the 60px rail. On mobile the footer is hidden, so a Focus icon button in the bottom dock is the Focus Mode entry point (touch devices have no `Cmd/Ctrl+B`). Focus Mode exit is animated with GSAP as a morph toward/away from the bottom-left corner (`scale 1 ↔ 0.05`, `transformOrigin: 'left bottom'`, alpha fade) replacing the old `display: none` toggle. Consumes `useSubject` / `useMaterial` via direct catalog hook imports, and `SyncStatusPill` via feature direct import.
- `bootstrap/` — Composition root: creates repositories, use cases, and the application graph. Registers cloud sync repositories (`syncQueueRepository`, `syncStateRepository`, `conflictDraftRepository`, `workerSyncTransport`, `dexieSyncReconciler`, `localStorageCredentialsProvider`), sharing transports (`workerShareTransport`), and use cases.
- `bootstrap.ts` — Application initialization: calls `DatabaseInitializer.initialize()` (opens Dexie database, runs legacy localStorage migration — **no seeding**; a fresh install boots with an empty library)
- `providers/AppProviders.tsx` — Astryx `<Theme>`, TanStack `<QueryClientProvider>`, `<ApplicationProvider>` (dependency-injected repositories + application services), and `<ToastProvider>` for user action notifications
- `providers/ApplicationContext.ts` — React context definition exposing the application graph (`useCases` plus repositories during migration)
- `providers/ApplicationProvider.tsx` — React context provider supplying one stable application graph to all feature hooks
- `providers/FocusModeContext.tsx` — Cross-cutting Focus Mode context (`FocusModeProvider` + `useFocusMode`), provided by `AppShell` so deeply-nested toolbars (reader, quiz canvas) react to the mode without prop-drilling; React context flows through portals

## Local Contracts

- High-level orchestration only. Business workflows belong in `src/application/`; domain rules belong in `src/domain/`.
- Providers are added only when cross-feature state sharing is needed.
- `bootstrap.ts` runs once at app startup (from `App.tsx` `useEffect`) — it initializes the database layer via `DatabaseInitializer`. No auto-hydration: the catalog is fetched independently when the Available UI requires it, and materials are imported on user action.
- `AppShell.tsx` mounts `OfflineBanner` as global chrome (connectivity status is shell-level, not feature-level). TanStack Query's `networkMode: 'offlineFirst'` default for queries and mutations (set in `providers/AppProviders.tsx`) is a hard requirement for offline operation — the app's data layer is local, so neither queries nor mutations may pause on `navigator.onLine`.
- Route state lives in `useAppRoute` via the `AppRoute` union (`library` | `explore` | `available` | `share` | `import` | `analytics` | `preview` | `terms` | `subject` | `workspace` | `quiz-canvas` | `quiz-session`). The `preview` route (`/available/:materialId/preview`) is the read-only preview surface for not-yet-imported catalog materials — it must never resolve from the local library (it resolves authoritatively from the catalog) and must never mutate beyond Add-to-Library. Document resolution is delegated to the reader feature's `useDocument` hook. Quiz entry points emit `QuizLaunchRequest` from Library and Reader screens. Quiz management navigates via `StudyMaterial`.
- Focus Mode contract: `useShellFocusMode` owns `isFocusMode` (initialized from `localStorage`, persisted on every toggle) and `AppShell` passes `isFocusMode` + `onToggleFocusMode` to `AppSidebar`. `Cmd+B` (macOS) / `Ctrl+B` (Windows/Linux) toggles it from any page. While active, the rail animates to 0 width (main spans 100% width), the mobile bottom dock morphs away and its bottom padding is removed, and a GSAP-animated floating logo button (`bottom: 16px`, `left: 16px`, `zIndex: 150`, `transformOrigin: 'left bottom'`) restores navigation — the sidebar and the FAB morph toward/away from the same bottom-left corner. The sidebar's 2-row brand footer card (logo, full title, version badge, Focus trigger) is the entry point in normal mode. The quiz canvas builder runs on the dedicated `quiz-canvas` route (URL-addressable, sidebar stays visible and collapsible, `onClose` returns to the material Manage tab). On mobile, the reader annotation toolbar and the quiz canvas card toolbar sit at `bottom: calc(84px + safe-area)` above the bottom nav; when Focus Mode hides the nav they transition down to `calc(16px + safe-area)` (0.35s) to use the freed vertical space. Both toolbars accept an optional `isFocusMode` prop that overrides `useFocusMode()` context.
- Query hooks may access repositories through DI during migration. Mutation hooks call `ApplicationContext.useCases` and never import concrete implementations directly.
- Install-discovery contract (community-reviewed, Aug 2026): no `beforeinstallprompt`/deferred-prompt machinery — Chromium already has native install affordances, so a prompt there is redundant. The affordances are the opt-in sidebar row (desktop/tablet) and the iOS-only one-time card; visit gating uses `STORAGE_KEYS.settings.visitCount` (incremented once per browser session via `session.visitMarked`) with the card shown from the second visit. "Not now" dismisses the card forever (persisted).
- First-run onboarding contract: one-time per browser, skippable, shown until `STORAGE_KEYS.settings.onboardingDone` is set. Rendered as a native `<dialog>` (`showModal`) so focus is trapped and Escape maps to Skip via the `cancel` event (never a bare close). The tutorial is app chrome (bundled, offline-safe, zero network dependency); its only side effect is syncing default terms via `SyncDefaultTermsUseCase` — triggered by Finish AND Skip (dismissal is never punished) — and the tutorial must never gate on network or imported library content.
