# src/application/ — Application Layer

## Purpose

Framework-agnostic use cases coordinating domain contracts between React adapters and infrastructure.

## Ownership

- `use-cases/quiz/` owns quiz session start (`StartQuizSessionUseCase`), atomic evaluation & submission (`SubmitQuizSessionUseCase`), and session abandonment (`AbandonQuizSessionUseCase`).
- `use-cases/quiz-management/` owns question and quiz authoring workflows, including `SaveQuizUseCase` (concurrency guard → draft validation → version increment rules → atomic commit via `QuizEditorService`, returns the `SaveQuizResult` discriminated union).
- `use-cases/library/` owns material create/update/touch workflows and the **single** removal workflow (`RemoveMaterialUseCase` — local-only removal of a material, delegating to the atomic cascade that clears the material row along with its questions, quizzes, document content, collection membership, and stored assets). There is no row-only delete use case by design — `LibraryRepository` exposes no delete, so a material row cannot be removed without its dependents. Library population happens via `use-cases/package/ImportStudyPackageUseCase` and `use-cases/sharing/ClonePublishedShareUseCase` — the catalog-era single/batch material import use cases were removed in the Phase 5 catalog retirement.
- `use-cases/reader/` owns annotation persistence workflows (`SaveHighlightUseCase`, `SaveDrawingUseCase`, `ClearAnnotationsUseCase`).
- `use-cases/content/` owns document content persistence workflows (`UpdateDocumentContentUseCase` — updates local markdown representation in Dexie without coupling to UI features or library discovery).
- `use-cases/flashcards/` owns spaced-repetition review state transitions and persistence coordination (`RecordFlashcardReviewUseCase`).
- `use-cases/analytics/` owns analytics coordination workflows (`GetGlobalAnalyticsUseCase`, `GetMaterialAnalyticsUseCase` — delegates raw data aggregation and calculations via `AnalyticsRepository` port).
- `use-cases/ai/` owns AI prompt/context orchestration, streamed chat execution with atomic turn persistence (`SendChatMessageUseCase` — stamps the persisted turn with the provider's token usage and the model that served it, on failed turns as well as completed ones; resolves grounding via `AiGroundingResolver` from thread state, attaching document markdown capped to the serving model's budget via `AiContextBuilder`; opens the turn atomically via `AiChatRepository.saveMessagePair` with a streaming placeholder), next-request grounding estimation (`GetAiGroundingContextUseCase` — shares `AiGroundingResolver` to return character counts and mode for the context meter without leaking document text), thread grounding mutation (`SetThreadGroundingUseCase` — partial update, rejecting 'whole' for global threads), new-conversation default preference (`SetGroundingDefaultUseCase` — device-local preference), selection-thread preference (`SetSelectionThreadModeUseCase` — latest vs distinct conversation for reader selection actions, device-local), preferred-model preference (`SetPreferredModelIdUseCase` — next-request model choice, device-local), and conversation-session lifecycle management (`ResolveAiThreadUseCase` — recovers turns abandoned mid-stream and resolves the newest session in scope without ever creating one; `CreateAiThreadUseCase` — always inserts a distinct session with thread grounding initialized from preference, rejecting 'whole' for global threads; `RenameAiThreadUseCase` — retitles a session without touching `updatedAt`, so recency keeps tracking conversation activity rather than edits; `GetAiThreadMessagesUseCase`, `DeleteAiThreadUseCase`, `ClearChatHistoryUseCase`). Sessions are scoped to a material and are local-only.
- `use-cases/ai/GetAiModelCatalogUseCase` resolves the model catalog the UI should offer, delegating the fetch/cache/bundle merge to the `AiModelCatalogRepository` port. It is the application-layer seam that keeps features out of infrastructure; the repository owns the fallback chain, so callers never handle a catalog failure.
- `use-cases/generator/` owns AI structured content synthesis workflows (`GenerateQuestionsUseCase`, `BatchCreateQuestionsUseCase`, `GenerateFlashcardsUseCase`, `BatchCreateFlashcardsUseCase`) coordinating `AiService.generateStructured`, section-bounded context extraction, strict domain draft validators, and atomic batch persistence to `QuestionRepository.createQuestionsBatch` with default `status: 'draft'`. Both generation use cases take the shared **`AiGroundingResolver`**: the source document is resolved from the request's `materialId` (never supplied by a caller), the model's `maxOutputTokens`/`maxDocumentContextChars` supply the budgets, the resolved model id is forwarded to the provider, and a material with no readable content fails as `EMPTY_DOCUMENT` instead of prompting on empty text. Both `execute` methods return `DraftBatch<...>` (`{ drafts, rejected }`) rather than a bare array: the valid drafts are kept and the malformed ones are reported, so the dialogs can name the shortfall instead of silently returning fewer items. The question system prompt is assembled per request — schemas for **only** the requested `types` are included (unused formats are more for the model to imitate, lengthen the prompt, and the tail of a long output is where it degenerates), and the rules name the failure modes actually observed from the default model (a dropped `true_false` prefix, an omitted `correctIndex`). Both prompts ask the model for **2-4 subject-matter topic tags** per item and rule out provenance tagging; the batch use cases persist `draft.tags` as-is with no marker of their own, so a generated row is classified by what it is about rather than by how it was authored.
- `use-cases/importer/` owns content extraction and import orchestration (`ExtractContentUseCase` — resolves format importer, executes extraction, and applies multi-pass Markdown conversion; `CommitImportUseCase` — generates material/document IDs, sets metadata, persists original file blob to `localAssets` (the Dexie v14 store keyed by `assetId`, indexed by `materialId`), and atomically registers material with `materials` and `documentContents` stores; `CleanupImportWithAiUseCase` — opt-in AI markdown cleanup accepting `CleanupImportRequest` (`{ markdown, title, model, catalog, signal }`) or backward-compatible positional arguments; resolves descriptor against custom passed catalog with fallback to `DEFAULT_AI_MODEL_CATALOG`, guards against oversized inputs via `descriptor.maxDocumentContextChars` without silent slicing, forwards `model` and `signal` to `streamChat`, rejects empty responses, and enforces client-side output truncation detection (`completionTokens >= descriptor.maxOutputTokens`) as a conservative, best-effort safeguard against ceiling hits pending formal Worker SSE `finish_reason` emission, returning dual-version original/cleaned diff).
- `use-cases/package/` owns study package materialization and import orchestration (`MaterializeStudyPackageUseCase` — extracts canonical material, questions, quizzes, and **every** stored asset of the material (via `AssetRepository.getByMaterialId`), strips personal learning/sync histories, assigns package-scoped `pkg_*` identifiers, numbers assets `pkg_asset_1..N` in a deterministic order (filename asc, asset id as tie-breaker) and rewires each `lc-asset://` URI by asset identity so a document's references stay paired with their own payload (legacy rows, whose `assetId` equals their `materialId` after the v14 migration, match the same rule); `ImportStudyPackageUseCase` — validates package graph, executes collision-free ID remapping, and delegates atomic persistence to `StudyPackageImportService`). Material `tags` round-trip portably: materialization copies `material.tags` into the `PackageMaterial`, remapping copies them to the remapped material, and import stamps them onto the persisted `StudyMaterial`.
- `use-cases/sharing/` owns cloud package distribution, discovery, and cloning (`PublishStudyPackageUseCase` — materializes portable `StudyPackage` and publishes to cloud via `ShareTransport`; `FetchPublishedShareUseCase` — fetches remote published share snapshot and runs defense-in-depth domain validation; `ListPublicSharesUseCase` — coordinates public shares listing with pagination and search; `ClonePublishedShareUseCase` — orchestrates fetch → validate → remap → commit transaction → download telemetry tracking; `TrackShareDownloadUseCase` — records download increments; `DeletePublishedShareUseCase` — authorizes and deletes remote published shares).
- `use-cases/sync/` owns application sync workflows (`ResolveConflictDraftUseCase` — coordinates document divergence resolution with keep_server, keep_local, or merge strategies via `ConflictDraftRepository.resolveConflict`; `TriggerSyncUseCase` — triggers single-flight sync convergence; `GetSyncStatusUseCase` — surfaces current sync status and diagnostics; `GetConflictDraftsUseCase` — retrieves unresolved conflict drafts).
- `collections/` owns playlist-model collection workflows (`CreateCollectionUseCase` — validates title, assigns `max(order) + 1`; `UpdateCollectionUseCase`; `DeleteCollectionUseCase` — deletes collection AND removes its `collectionMaterials` junction rows; `AddMaterialToCollectionUseCase` — rejects duplicates, auto-calculates `max(order) + 1`; `RemoveMaterialFromCollectionUseCase`; `ReorderCollectionMaterialsUseCase`).
- `sync/` owns cloud synchronization convergence orchestration (`SyncEngine` coordinating the 4-step convergence cycle: pull → push outbox → pull catchup → finalize idle via `SyncReconciler` domain port), single-flight mutex (`syncMutex` merging concurrent calls and executing requested follow-up cycles), observable in-memory projection (`SyncStatusStore` with `rehydrateFromStorage` and reactive listeners), and exponential backoff retry policies (`syncRetryPolicy` / `calculateRetryDelay`). Browser lifecycle triggers (`online`, `visibilitychange`, timers) are decoupled into `BrowserSyncLifecycle` in infrastructure.
- `quiz-management/drafts/` owns the quiz canvas Application Session DTOs (`QuizDraft`/`QuestionDraft`), draft validation (`quizDraftValidation`), the `QuizDraftRepository` crash-recovery contract, and draft seeding helpers. Drafts carry UI session concerns (`tempId`, `isDirty`) and are never persisted to the Question Bank or Quiz Catalog.

## Local Contracts

- Use cases and application services never import React, TanStack Query, Dexie, browser APIs, features, or UI components.
- `SyncEngine` encapsulates the 4-step sync convergence protocol (pull -> push batches -> pull -> finalize idle), enforces a single-flight mutex with follow-up cycle execution, handles offline detection gracefully, and updates `SyncStatusStore` through the `SyncReconciler` port.
- Dependencies are strictly domain repository/service contracts, domain models/services, and application input/output types.
- React hooks remain thin adapters for cache behavior and presentation concerns.
- `SaveQuizUseCase` never touches IndexedDB draft storage or query caches — draft deletion and cache invalidation belong to the UI editor layer.
- Version increment rule: `questionVersion` bumps only when question prompt or answer payload content changes; points, order, and quiz-specific metadata never bump.

## Work Guidance

- Keep persistence details in repository implementations.
- **Primary Unit Test Discoverability & Colocation (ADR-012)**: Each application use case has a dedicated, clearly identifiable primary unit-test file named after the use case (`<UseCaseName>.ts` $\leftrightarrow$ `__tests__/<UseCaseName>.test.ts`). Tests assert application orchestration boundaries, domain invariants, and failure propagation using pure domain port mocks (zero live IndexedDB or network dependencies). Supplementary specialized suites are authorized alongside primary unit tests when testing complex interactions — `use-cases/package/__tests__/packageRoundtrip.test.ts` (multi-hop association) and `packageRoundtripBytes.test.ts` (byte identity, `// @vitest-environment node`, see `src/infrastructure/AGENTS.md`) cover the `.lcpack` round-trip contract.
