# src/features/collections/ — Playlist Collections Bounded Context

## Purpose

Owns playlist-model collection presentation and membership state: collection query/mutation hooks and cache keys. Collections group materials via the `collectionMaterials` junction; each collection keeps its own independent material ordering.

## Ownership

- `queries/` — Cache key definitions:
  - `collectionQueryKeys.ts` — Query key factory for the `['collections', ...]` namespace (`lists`, `details`, `detail(id)`, `materials(collectionId)`, `materialCollections(materialId)`, `assignedMaterialIds`, `materialCounts`).
- `types/` — Feature contracts:
  - `collectionQuizTree.types.ts` — `CollectionQuizItem` (quiz id, material id, title, question count, optional description) and `CollectionQuizMaterialGroup` (material groups owning quiz items).
- `hooks/` — Collection state hooks (DI via `ApplicationContext`, never concrete infrastructure):
  - `queries/useCollections.ts` — All collections sorted by `order`.
  - `queries/useCollection.ts` — Single collection by ID.
  - `queries/useCollectionMaterials.ts` — Junction-ordered `StudyMaterial[]` for a collection (links via `CollectionMaterialRepository`, materials via `LibraryRepository`, order re-applied after map lookup).
  - `queries/useMaterialCollections.ts` — `Collection[]` + `collectionIds` containing a material.
  - `queries/useAssignedMaterialIds.ts` — `Set<materialId>` of materials belonging to **at least one** collection. The inverse read model behind the Library membership lens: one `Set` answers both the `collected` and `uncollected` predicates. Returns a module-level stable empty set while loading so callers' memo dependencies do not churn.
  - `queries/useCollectionMaterialCounts.ts` — `Record<collectionId, member count>` for sidebar badges (links via `CollectionMaterialRepository`, key `materialCounts()`).
  - `queries/useCollectionQuizTree.ts` — Quiz tree for a collection: fetches via the `QuizRepository` port (`getQuizzesForMaterials`), groups by material in collection material order, derives counts from `quiz.questionIds.length`. Key: `[...collectionQueryKeys.materials(collectionId), 'quiz-tree', materialIds]` (materialIds included so the tree refetches once the collection's materials resolve — the workspace hero reads this hook before materials load).  - `components/` — Feature-owned presentation:
  - `CollectionShelf.tsx` & `collectionShelf.stylex.ts` — Library's Collections shelf: a responsive one/two/three-column band of playlist cards (collection icon + color, title, live member count, chevron) stacked above the materials grid, plus an inline "No collections yet" prompt and a create affordance. **Pure presentation** (screen resolves collections + counts and passes them in), so it stays fast-refresh-clean and independently testable. Optional `limit` caps the rendered cards while the header count reflects the full list — the screen's overview stepper owns growing it. Past `VIRTUALIZE_AFTER_ITEM_COUNT` (and never under a `limit`) the grid swaps to `VirtualShelfGrid` (window-virtualized aligned rows in live 1/2/3 lanes, measured per row). Both the plain grid and the virtual path delegate the inner card button to `CollectionCard` — markup lives in exactly one place.
  - `CollectionCard.tsx` — Single collection playlist card (icon + color, title, `{count}` member count, chevron) on `collectionShelf.stylex.ts`. Pure presentation, props `{ collection, count, onOpen }`; parents resolve the count from `counts[collection.id] ?? 0`. `VirtualShelfGrid` keeps its virtualizer + `minWidth: 0` cell wrapper around it.
  - `CollectionNavItem.tsx` — Style-agnostic collection nav row unifying `DesktopSidebar`'s `CollectionNavButton`, the compact rail row, and the dock drawer row. Owns only shared structure (collection-color-tinted icon via persisted user-data `color`, ellipsis title, count badge); styling stays with the caller via `stylex.props(...)` slot props (`buttonProps`, `iconWrapProps`, `labelProps`, `badgeProps` — typed as `CollectionNavItemSlots`) plus `tintTarget` (`icon` for sidebar/drawer, `button` for the rail row whose `color` cascades), `role`, and `iconSize`. Each layout pre-binds its slots through a local factory (`sidebarNavItemSlots` / `railNavItemSlots` / `drawerNavItemSlots`) so row JSX stays declarative. Never imports layout/navigation styles — the features → app direction stays one-way.
  - `CollectionAppearancePicker.tsx` — Shared color + icon picker unifying the copy-pasted swatch/icon `radiogroup` blocks from both collection dialogs. Consumes `collectionAppearance.ts` + `collectionModal.stylex.ts`; props `{ color, icon, onColorChange, onIconChange, labelIds }` (`labelIds` defaults to the create dialog's `collection-*-label`; edit passes its `edit-collection-*-label` pair). Toggle-off preserved: re-clicking a selected swatch/icon yields `undefined`.
  - `CollectionQuizExplorer.tsx` — Quizzes tab explorer: shared `SearchInput` with a debounced (200ms) title search, material accordion groups with per-material and per-quiz checkboxes, `Select All ({n})` checkbox + `{n} quizzes · {m} questions` toolbar summary, alternating Foundations/Apply difficulty chips + `X questions` chips per quiz row (the chips differentiate through the theme's `teal`/`orange` hue families — `var(--color-{text,background,border}-teal|orange)` — not literals), empty states, and a fixed floating glass action bar (Zap mark, single/multi title copy, `{n} selected · {m} questions` subtitle, Clear + `Start Quiz: {title}` / `Start Unified Quiz ({n} quizzes · {m} questions)` actions) emitting single (`type: 'quiz'`) or unified (`type: 'quizzes'`) `QuizLaunchRequest` via `onStartQuiz`. The bar uses the token glass recipe (`--color-background-surface` + blur, `--color-border`, radius 20, dock shadow — no hardcoded palette) and is nav-aware per breakpoint (mobile: 16px gutters parked above the 60px dock incl. safe-area; tablet: clears the 60px floating rail; desktop: centered in the 240px-sidebar content region, reclaiming the offset in Focus Mode via `useFocusMode`); at ≤640px it stacks info above full-width actions. The bar's offsets carry a 0.35s transition matching the rail's Focus collapse so it glides with the sidebar instead of jumping. Container reserves bottom padding while the bar is visible.
  - `mutations/useCreateCollection.ts`, `mutations/useUpdateCollection.ts`, `mutations/useDeleteCollection.ts` — Delegate to `useCases.collections.*`, invalidate `collectionQueryKeys.all` (+ `detail(id)` on update).
  - `mutations/useAddMaterialToCollection.ts`, `mutations/useRemoveMaterialFromCollection.ts` — Invalidate `materials(collectionId)`, `materialCollections(materialId)`, `assignedMaterialIds`, `materialCounts`.
  - `mutations/useReorderCollectionMaterials.ts` — Optimistically reorders `materials(collectionId)` query cache on mutate and invalidates `materials(collectionId)`, `materialCounts` on settle with rollback on error.
- `modals/` — Self-contained collection dialogs (no hook/query dependencies; all data and callbacks flow in via props):
  - `collectionModal.stylex.ts` — Shared `*.stylex.ts` styles for `CreateCollectionModal`/`EditCollectionModal` (form rhythm, token-based swatch/icon selection rings, one `modalFooter`/`modalActions` pattern rendered through `Dialog footer=`).
  - `CreateCollectionModal.tsx` — Create dialog: required title (autofocus, submit disabled when blank), optional description (`TextArea`), and appearance via `CollectionAppearancePicker` (soft color preset swatches + icon selector, `role=radiogroup` semantics; clicking a selected swatch/icon deselects it). Draft resets on reopen via guarded render-phase adjustment. Emits trimmed `title` + optional `description`/`icon`/`color` through `onSave`.
  - `EditCollectionModal.tsx` — Edit dialog pre-filled from the `collection` prop; appearance via `CollectionAppearancePicker` with the `edit-collection-*-label` ids; re-seeds its draft when the modal opens or a different collection is targeted; emits `(id, { title?, description?, icon?, color? })` through `onSave`.
  - `collectionAppearance.ts` — Shared registry mapping persisted plain-string `icon`/`color` values to lucide components (`COLLECTION_ICONS`, `getCollectionIcon`, default Folder) and soft hex swatches (`COLLECTION_COLOR_PRESETS`: Blue, Green, Purple, Amber, Rose, Cyan). Also owns the colour derivations shared with the workspace hero — `collectionTint(color, alphaHex, percent)` (hex alpha suffix, `color-mix` fallback) and `collectionHeroBackground(color)` (radial tint gradient). Both derive from the collection's **persisted** `color` (user data, not a design token). Kept out of component files so they stay fast-refresh-clean.

## Local Contracts

- **Directed Dependencies (ADR-014)**: Depends unidirectionally on `materials/` (`MaterialCard`, `LibraryRepository` port, `materialQueryKeys` invalidation scope is separate), plus a type-only dependency on `quiz/types/quizFeature.types` (`QuizLaunchRequest` for the explorer launch contract — no runtime quiz imports, DAG stays acyclic). Must not depend on `app/screens/`.
- Query hooks read through `context.repositories.collection` / `collectionMaterial` / `library`; mutation hooks delegate exclusively to `context.useCases.collections.*`.
- `modals/` are pure presentation: they never import hooks, repositories, or infrastructure — parents own data fetching and pass `collections`, `assignedCollectionIds`, and `onToggle`/`onSave` callbacks. Non-goals in force: never add hook/query imports here; `src/app/routing/` and `ShellRoutes.tsx` are owned elsewhere.
- Route-level workspace orchestration belongs to `src/app/screens/collection-workspace/CollectionWorkspaceScreen.tsx` (mounts `EditCollectionModal`, drives edit/delete mutations). Collection creation is launched from the Library screen (`LibraryScreen` → `LibraryModals`) and from `CollectionShelf`'s create affordance, in addition to the sidebar.
- **Single assignment surface.** Material-to-collection assignment lives exclusively in `MaterialCard`'s inline collections popover (`features/materials`). The former `ManageMaterialCollectionsModal` was deleted along with its test — it had no caller, and the popover now carries the modal's two genuine advantages: it stays open across toggles (multi-assign in one pass) and disables a row while its mutation is in flight. Do not reintroduce a second assignment UI.
- Shell discovery belongs to `src/app/layouts/navigation/DesktopSidebar.tsx` (`CollectionsNav` mounts `CreateCollectionModal`, navigates to the new collection on save).
