# src/features/quiz-management/ — Quiz & Question Management

## Purpose

Authoring feature for creating, editing, publishing, and archiving questions and quizzes. Separate from the learner quiz-taking experience (`src/features/quiz/`). Provides a Question Bank manager, Quiz Catalog, the quiz canvas builder (Google Forms-style authoring, rendered on a dedicated `quiz-canvas` app-shell route so the global sidebar stays visible), type-specific question editors, and publishing workflows.

Idle wake: `ResizeObserver` on the target node + the title card (meta growth moves the grid) + `window resize`. While a card is dragged the loop is suspended (toolbar frozen); on release it re-runs and glides to the resting target at the new slot. Scroll pinning: a scroll + rAF geometry evaluator (NO `IntersectionObserver` — it watches the CARD's rect, but the toolbar is far shorter than an expanded card, so a card-based trigger fires too late on exit (toolbar fully clipped while the card still "intersects") and unpins too early (40px card overlap while the toolbar is still mostly clipped); an IO also can't express a hypothetical rect for a wrapper whose real rect is meaningless while `position: fixed`). The evaluator computes the toolbar's would-be anchored rect — the active card's RESTING doc-space top (the same constant the chase's one-glide targets: collapsed-height cache + callout estimate, clamped like the chase) + the toolbar's OWN height — against the VIEWPORT's visible box — WINDOW-SCROLL mode: the page owns the scroll (scroll events on `window`, scrollTop = `window.scrollY`), and the visible box is inset-derived — `topInset` (the sticky header's height, measured by the builder) → `innerHeight − bottomInset` (a constant during layout transitions, so a focus change never produces a transient pin→unpin snap); when the hypothetical footprint's LEADING edge leaves the visible box minus a scroll-speed anticipation lead (`hypoTop < topInset + lead` for top-pin, `hypoBottom > effectiveBottom − lead` for bottom-pin, where `effectiveBottom = innerHeight − bottomInset` is the viewport's visible bottom minus the shell-supplied bottom-bar inset (the mobile bottom nav at ≤768px, measured by AppShell from `main`'s own declared bottom padding — 0 at >768px and in Focus Mode — and threaded down via `QuizCanvasBuilder` → `QuizCanvasQuestionList` → lane) — so a bottom-pinned toolbar stays ABOVE the bar, never under it (tuned geometry: at 700×900 it lands 32px above the nav top — 796 vs 828 — re-verify with a probe if the header/main relationship ever changes), and is ALREADY pinned the moment it would start scrolling out of view, a true sticky toolbar) the toolbar pins to the visible box edge (viewport-relative but inset-aware — `topInset + PIN_MARGIN` / `innerHeight − effectiveBottom + PIN_MARGIN` — so a top-pinned toolbar locks just BELOW the sticky header, never over it, and a bottom-pinned one stays above the bar; `left` is captured so the toolbar stays in its lane column) so its actions stay reachable. Geometry-based side decision (which edge the footprint is leaving); scroll speed only feeds a short pin-anticipation lead (`MAX_PIN_LEAD` ≤ 32px, capped below `PIN_REENTER` so the hysteresis gap always holds) so a fast fling locks the toolbar in while it is still at the edge instead of popping it in from above (no brief header overlap); unpin requires the footprint to fully clear both visible edges by the 40px `PIN_REENTER` margin (symmetric full-fit), and the gap between the pin line (at the edge) and the gate (40px inside) is the hysteresis that prevents anchored↔pinned boundary flip-flop. While pinned the chase loop is suspended (`pinState`, mirrored locally so re-arms while pinned — activeCardId swap, drag release, Focus Mode toggle — stay in sync with the DOM); unpinning converts the pinned viewport position back into the chase's scroll-invariant content space (`docY = wrapperRect.top − bodyRect.top`, NO scrollTop term) so the chase glides from where the toolbar visually was instead of jumping — the unpin handoff is seamless (docY = current visual position) and the return glide to the card is owned by the chase re-arm, not an explicit tween. Pinning is a CONTINUOUS LOCK (0.25s `power2.out` ease from the toolbar's current on-screen position into the pinned position — no fade, since the edge-touch trigger pins while the toolbar is already at the edge; the settle runs on transform `y` deliberately, because `refreshPin` re-writes `top`/`bottom`/`left` on the `pinState` re-arm ~1 frame later, which would cut a top/bottom tween to a single frame, while transform `y` is untouched by the geometry writer). A pin-SIDE flip (top ↔ bottom) is the one case where the toolbar is NOT at the edge it's pinning to — the settle duration scales with the cross-viewport travel (distance/`PIN_GLIDE_SPEED`, capped at `REFLOW_DURATION`) so the toolbar visibly glides between edges instead of whipping; the `−PIN_MARGIN` settle-start clamp applies to TOP pins only (the never-paint-above-the-header guarantee for violent-fling pin-ins), never to bottom pins — clamping a bottom pin's large negative `fromY` (a top→bottom flip) was what teleported the toolbar in one frame while the 0.25s settle animated a 16px sliver. Pinned geometry refresh: INSET-DRIVEN re-arms (a Focus Mode toggle at ≤768px flips `bottomInset` — the `prevBottomInsetRef` detects them) ANIMATE the bottom-pinned toolbar's offset instead of re-reading it — one `bottom: newInset + PIN_MARGIN` layout write, then a TRANSFORM-y fromTo from the toolbar's current visual spot to 0 (0.35s power2.out, matching the rail/pill motion language; direction falls out naturally, ±88px) so the toolbar slides up/down with the nav instead of snapping — the slide is on `y`, NOT `bottom`, because the toggle is the busiest frame (document relayout + double render) and a per-frame `bottom` tween would stutter there, and because `refreshPin` re-writes top/bottom/left on the `pinState` re-arm ~1 frame later (which would cut a bottom tween to a single frame) while transform `y` is untouched by the geometry writer; the tween only fires when the footprint still violates the NEW effective bottom (`willStayPinned` mirrors the evaluator's unpin gate EXACTLY — both edges + PIN_REENTER margin — identical math, so the two can only disagree if the geometry changes between frames, which self-corrects on the next scroll) — if the freed space revealed the card, the re-arm does nothing and the evaluator un-pins next frame, the chase gliding the toolbar back to its card from its current visual spot (seamless, no jump). All other re-arms (rail animation, banner mount, resize) keep the INSTANT `refreshPin` re-read: a `ResizeObserver` on the wrapper/grid/title re-reads it whenever their boxes change (the GSAP sidebar-rail animation on Focus Mode toggles, recovery-banner mount) AND a `window resize` listener re-reads it on every viewport size change — a width resize recenters the maxWidth-capped canvas body, sliding the lane horizontally while the observed boxes keep their SIZE (ResizeObserver only reports size, so it never fires for this — verified in a headless probe: zero RO callbacks while the lane moved ~110px and the pinned toolbar stayed behind), making the window `resize` event the reliable signal; it reads live rects post-layout so the pinned `left`/`top`/`bottom` always match the moved lane. On mobile (<640px) the lane collapses, pin styles are cleared, and `pinState` resets to anchored so returning to desktop resumes the chase; the toolbar renders as a floating bottom glassmorphism bar |

## Local Contracts

- No cross-feature imports — this feature does not import from `src/features/quiz/`
- Query repository access via application context; mutations call `context.useCases.quizManagement`
- Query keys match the assessment namespace: `['assessment', 'questions', materialId]` and `['assessment', 'quizzes', materialId]`
- `QuestionStatus` lifecycle: `draft` → `published` → `archived`
- `QuizStatus` lifecycle: `draft` → `published` → `archived`
- Archiving is soft-delete — never hard-deletes questions that may be referenced by quizzes
- `QuizQuestion` version pinning: quizzes snapshot `questionVersion` at creation time
- UI components contain zero grading, scoring, or persistence logic
- 3-layer save model: (1) canvas state in `useQuizCanvas`, (2) autosaved `QuizDraft` in Dexie `quizEditingDrafts` via shared `useDraftAutosave` (2s debounce / blur / unload / 30s max throttle), (3) explicit Save Quiz → `SaveQuizUseCase` atomic transaction. The Question Bank and Quiz Catalog are only written on explicit save; drafts exist purely for crash recovery
- Question Bank is the single source of truth: imported canvas cards reference `questionId`; editing them updates the bank question on save and bumps `questionVersion` when prompt/payload content changes (points/order/metadata never bump). Bank-linked cards cannot change type. Duplicated cards detach from the bank (new question on save)
- After save success, `useQuizCanvasEditor` deletes the local draft, invalidates `['assessment']` caches, and rebinds the session to the saved `quizId`
- Canvas motion is owned by GSAP & CSS: `Draggable` for drag reorder (direction-aware midpoint crossing swaps with hysteresis; bounded by the whole outer canvas column element (meta card headroom above Q1, question grid, reserved bottom dropzone `BOTTOM_BUFFER = 160`); GSAP re-measures the element bounds into each card's local space on every press, so any card — collapsed or expanded — can swap into any slot end-to-end without forced height clipping; dragging auto-collapses the held card to its compact summary (`COMPACT_HEIGHT = 76`) and re-renders active cards as clean collapsed summaries (`isDragging` → `effectiveIsActive`, no clipped editor) so it glides lightweight through tight compact steps; drag/active card shadows are CSS-owned classes (`cardActive` / `cardDragging`), so GSAP tweens only scale/zIndex and never `box-shadow`, and on release the physical push engine re-expands it to full editor view at its new slot; after a real drag the trailing browser `click` is suppressed for ~150ms, scoped to the dragged card, so dropping never accidentally expands a card; the active-card toolbar is a `toolbarLane` sibling whose position wrapper (`position: absolute; top: 0`) runs a rAF follow loop that glides to a computed RESTING target — the active card's top at all-resting heights: per-card collapsed-height cache (`collapsedHeightsRef`, sampled at `settleLayout` for inactive error-free cards) + `COMPACT_HEIGHT` fallback + a deterministic error-callout estimate from the `errors` prop — issuing ONE `0.35s` `power2.out` glide during the transition (toolbar and collapse arrive together: no chasing a moving rect, no dip/wobble, no timing bet), keep-pace mode re-targets the live position with velocity-scaled durations while the user is actively scrolling; then a drift-verify phase trusts the live position once the layout settles and nudges residual estimate error with short tweens; the loop settles after 6 stable frames, wakes on `ResizeObserver` (target + title card)/`window resize`, and suspends (freezes) while dragging; scroll pinning: a scroll + rAF geometry evaluator (no `IntersectionObserver` — the toolbar is far shorter than an expanded card, so a card-based trigger fires too late, and an IO can't express the wrapper's hypothetical rect) computes the toolbar's hypothetical anchored footprint (the card's RESTING doc-top + own height, clamped like the chase — a constant during layout transitions, so a focus change never causes a transient pin→unpin snap) against the viewport's visible box (window-scroll mode: `topInset` → `innerHeight − bottomInset`); the toolbar pins when the footprint's LEADING edge leaves the visible box minus a scroll-speed anticipation lead (`hypoTop < topInset + lead` / `hypoBottom > effectiveBottom − lead`, the viewport bottom minus the shell-supplied bottom-bar inset — already pinned the moment it starts to leave, sticky-style trigger) via `position: fixed` in the lane column — geometry-based side decision (scroll speed only feeds the lead and the velocity-scaled keep-pace chase), unpin requires the footprint to fully clear both visible edges by the 40px `PIN_REENTER` margin (symmetric full-fit; the gap between the edge and the gate is the hysteresis against boundary flip-flop), chase suspended while pinned and resumed on unpin (viewport position converted to scroll-invariant content-space `docY = wrapperRect.top − bodyRect.top` so the chase glides, no jump), pinned geometry refreshed by a wrapper/grid/title `ResizeObserver` + `window resize` (viewport size changes, Focus Mode rail animation, banner mount)), tweens for accordion reflow, and frame-synced physical-push height tweens for expand/collapse (card height animates from its last stable snapshot while `onUpdate` repositions lower cards each frame). Do not reintroduce HTML5 drag-and-drop into `QuizCanvasQuestionList`; keyboard-accessible reordering lives in the active-card toolbar (Move up/down)
