# src/features/importer/ — Content Importer Feature
 
## Purpose

User-facing 5-step import wizard allowing learners to ingest external study materials (PDFs, photos of notes), review and edit Markdown via Lexical Writer, optionally clean up text with AI diff comparison, and persist to local library storage with original asset preservation.

## Ownership

- The route screen and stepper live in the screen layer (`src/app/screens/importer/` — route-level composition, ADR-014); this feature owns the step views, the state machine, and the StyleX rules.
- `components/`
  - `ImportDropZone.tsx` — Drag-and-drop file ingestion zone with format pill hints, file validation, and OCR engine selection via the shared `SegmentedControl` (Local Tesseract vs AI Vision MAX, disabled — `aria-disabled` on the segment — when offline).
  - `ImportFileCard.tsx` — File queue card with the canonical `ImportStatusBadge`, size, and a shared `Button` (ghost, icon-only) remove action.
  - `ImportStatusBadge.tsx` — Canonical status pill (`badgedot`) shared by the queue card, the review toolbar's file selector, and the progress view: 11px/600 type, `2px 8px`, `--radius-full`, one muted-fill + solid-hue pair per state (`pending`, `review`, `done`, `error`), and an accent `Loader2` spinner — carrying `role="status"` — for `extracting` / `saving` instead of a sixth hue. The label always renders beside the dot, so state never rests on colour alone.
  - `ExtractionProgressView.tsx` — Multi-file extraction progress bar with active phase labels (page tracking, `ai-vision` visual indication with Sparkles and accent role tokens, rate-limit cooldown countdown) and cancellation via a shared `Button`.
  - `ImportReviewView.tsx` — Review step: a review-level toolbar rendered above the panes in **every** view mode (file selector, status badge, page tag, the `[ Split | Editor | Preview ]` `SegmentedControl`, AI model picker, and the AI cleanup button whose accessible name carries the in-flight/cooldown state — the switcher must never live inside a pane, or picking Editor/Preview would unmount the only way back), Lexical `WriterEditor` in Split/Editor, `MarkdownViewer` in Split/Preview, the shared `Dialog` diff comparison with Accept/Reject, and the partial-extraction banner plus AI error surfaced above the panes so they stay visible in every mode. **File switching (Option B, Sep 2026):** the permanent 220px `Files` sidebar is gone so the panes keep the full width, and the toolbar's info block is now the selector. One candidate renders a static icon + filename; several render a trigger (`resume.pdf (1 of 3) ▾`, `aria-haspopup="listbox"` + `aria-expanded`) whose popover (`role="listbox"`, `aria-label="Select file to review"`) lists every candidate with file icon, `ImportStatusBadge`, and a degrades-to-nothing page tag. Options are `role="option"` with `aria-selected`; picking one selects it, closes the popover, and returns focus to the trigger, and dismissal is a document `pointerdown` outside trigger/popover or `Escape`. Options are tabbable, but arrow-key navigation inside the listbox is **not** implemented yet.
  - `MaterialDetailsView.tsx` — Title assignment step: one Card surface per candidate (document icon, filename, file size, word count, and page count when the extraction knows it) over the shared `Input`, with the `Material Details` `h3` kept verbatim as an E2E contract. Word count comes from the extraction stats when present and is otherwise estimated from the current markdown (whitespace tokens carrying a letter or digit). It deliberately owns **no** commit action — the wizard footer owns `Save to Library`.
  - `ImportResultView.tsx` — R1 study handoff surface: a neutral centred column (max 520px) with one 56px `--color-success-muted` badge, an `h2` (`Import Successful`) plus count line, and one row per material (accent icon tile, ellipsised title, `Saved to Library` status, `ghost` Open Material action). The saturated success card is gone — `--color-success(-muted)` now marks only the badge and each row's status, where it describes the object instead of colouring the surface. Row actions are `ghost` so the deck keeps the single `primary` (`Open in Workspace`, single material only).
- `hooks/`
  - `useImportSession.ts` — 5-step state machine with bounded concurrency (max 2 concurrent extraction jobs), `ocrEngine` selection, progress tracking (`progressMap`), and `AbortController` cancellation per candidate (`cancelExtraction`).
  - `useAiCleanup.ts` — Opt-in AI markdown cleanup hook managing whole-document cleanup, selection-based cleanup (`cleanSelection`), section-by-section progress (`progress`), candidate-switching abort, rate-limit cooldown, and mid-run failure resumption (`retryRemaining`).
  - `useImporterContext.ts` — Dependency injection consumer for application use cases.
- `styles/importer.stylex.ts` — StyleX styles for the step body, drop zone, file cards, the status badge set (`badgedot` / `dot` / `badge*` / `dot*`), the pinned wizard action bars (`actionBar` + `actionBarEnd` / `actionBarSplit`), the review shell (`reviewShell` / `reviewToolbar*` / `reviewBody` / `reviewCenter` / `reviewRight` / `pageTag`), the file selector (`fileSelectorTrigger` / `fileIndex` / `fileKindIcon` / `popover` / `popoverItem*` / `popoverFilename`), the details cards (`detailsHeading` / `detailsCard*`), and the results view (`resultContainer` / `successHeader` / `successBadge` / `resultTitle` / `resultSubtitle` / `resultMaterial*` / `resultActionDeck`). `iconSpin` is a StyleX `keyframes` spin with a `prefers-reduced-motion` off-switch — the retired `className="animate-spin"` was a Tailwind leftover the project never defined, so spinners were static. Every colour is an Astryx role token (`var(--color-*)`); no literal hex lives here — the one deliberate exception is the file-selector popover's elevation `boxShadow`, which uses a literal translucent rgba because the theme's shadow scale is tuned for cards (the app's other floating surfaces, `ActionMenu` and the compact-collections popover, do the same). Borders carrying a token are written as longhand triplets (`borderWidth` / `borderStyle` / `borderColor`) because StyleX drops a `border*` shorthand whose value contains `var()`. Radii come from the theme's own scale — `--radius-full` for circles/pills, `--radius-element` / `--radius-container` for surfaces; **`--radius-sm`/`--radius-md`/`--radius-lg` do not exist in `lunaclairTheme`** and an undefined radius token drops to the initial value (square corners) rather than degrading.

## Local Contracts

- Importer is code-split and lazy-loaded via `React.lazy` behind `/import` route to keep main app bundle lean.
- Primitive-only chrome: the wizard and its step views render the shared adapters (`Page`, `Button`, `Input`, `SegmentedControl`, `Dialog`) instead of raw `<button>` / `<input>` / bespoke overlay markup, and reference colour by role token — never a literal hex. The file-selector popover is the one exception: it needs `role="listbox"` / `role="option"` rows carrying icons, badges, and page tags, which no shared adapter provides (the shared `Selector` is a labelled combobox with plain string options, and `ActionMenu` is an icon-only ellipsis menu). If a generic popover/listbox primitive ever lands in `src/shared/ui`, fold this onto it.
- Status badges are the canonical `badgedot` pattern (`ImportStatusBadge`) and only ever use the sentiment roles `--color-{success,warning,error}` plus accent for in-flight work; `--color-danger` does not exist in Astryx and must not be introduced.
- Non-destructive re-entry: extraction only ever targets `pending` / `error` candidates (`useImportSession.startExtraction` filters the queue), so returning to Files and re-running the step can never discard markdown edits or accepted AI cleanups. Step 1's primary action is derived from candidate state by the screen layer (`src/app/screens/importer/utils/selectingAction.ts`) to keep that promise visible in the label.
- The review step's AI cleanup action keeps its state in the accessible name (`AI Cleanup (12s)` / `Cleaning with AI...`), so the countdown and in-flight state stay available to assistive technology, not just visually.
- Direct-path feature contracts only (ADR-010): consumes `WriterEditor` from `src/features/writer/components/WriterEditor`, `MarkdownViewer` from `src/features/reader/components/MarkdownViewer`, and `useAiModelSelection`/`AiModelPicker` from `src/features/ai/`.
- Concurrency limit: extraction queue runs with a maximum of 2 parallel worker jobs to avoid browser memory pressure.
- User-in-the-loop: AI cleanup is strictly opt-in and generates a visual diff; AI never silently modifies extracted text without explicit Accept. Candidate switching cancels in-flight cleanup and clears diff state; candidateId and original text must match upon acceptance.
- Multimodal Vision Extraction: AI Vision (`ukisai-swift-max`) digitizes scanned PDFs/images directly into structured Markdown tables and formatting. Importers execute AI Vision strictly on `ocrEngine === 'ai-vision'` with zero silent fallback to local Tesseract, emitting `phase: 'ai-vision'` extraction progress and separate `visionPages` statistics. Enforces 12-second pacing between request starts and abortable rate-limit cooldown (429 `retryAfterSeconds`, retrying up to 2 times).
- Cancellation & Partial Result Contract: On user cancellation, ongoing extraction preserves all pages extracted up to page `i-1`, marks `isPartial: true`, and presents the partial document in `ImportReviewView` with a warning banner.
- Local-first offline invariant: Tesseract WASM is the default offline-capable extractor; AI Vision is strictly an opt-in cloud enhancement requiring `navigator.onLine` and MAX availability.
