# src/features/importer/ — Content Importer Feature
 
## Purpose

User-facing 5-step import wizard allowing learners to ingest external study materials (PDFs, photos of notes), review and edit Markdown via Lexical Writer, optionally clean up text with AI diff comparison, and persist to local library storage with original asset preservation.

## Ownership

- The route screen and stepper live in the screen layer (`src/app/screens/importer/` — route-level composition, ADR-014); this feature owns the step views, the state machine, and the StyleX rules.
- `components/`
  - `ImportDropZone.tsx` — Drag-and-drop file ingestion zone with hover, drag-over feedback (`isDraggingOver`), keyboard `Enter`/`Space` activation, format pill hints, file validation, and a stacked full-width extraction engine card (`engineCard`) hosting title, hint, and the OCR engine selector via the shared `SegmentedControl` (`layout="fill"`, Cpu/Sparkles icons: Local Tesseract vs AI Vision MAX, disabled — `aria-disabled` on the segment — when offline). Progressive disclosure: `engineCard` is conditionally rendered via `showEngineConfig`, hidden when there are zero unextracted candidates (i.e. empty queue or when all candidates have already been extracted to `review`), and revealed whenever `pending` or `error` candidates exist or when a reviewed candidate is reset via `Re-extract`.
  - `ImportFileCard.tsx` — Responsive file queue card using `fileMain` (icon tile `fileIconTile`, `fileInfo` with `minWidth: 0` and word-break wrapping, and `fileBadge`), canonical `ImportStatusBadge` (supporting `isPartial`), size, partial extraction details (`Partial (X of Y pages)`), and action deck: explicit `Review Partial` / `Review` action (`onReview`), `Re-extract` / `Retry` action (`onRetry`), and a shared `Button` remove action. Stacks responsively on mobile (`<= 768px`) with full-width file info and a separated bottom action bar to eliminate flex squeezing and horizontal button clipping.
  - `ImportStatusBadge.tsx` — Canonical status pill (`badgedot`) shared by the queue card, the review toolbar's file selector, and the progress view: 11px/600 type, `2px 8px`, `--radius-full`, one muted-fill + solid-hue pair per state (`pending`, `review`, `done`, `error`), and an accent `Loader2` spinner — carrying `role="status"` — for `extracting` / `saving` instead of a sixth hue. The label always renders beside the dot, so state never rests on colour alone. Supports `isPartial` to render a `partial` pill for partial extraction results.
  - `ExtractionProgressView.tsx` — Multi-file extraction progress view with candidate file cards with file type icon tiles (`FileText`/`ImageIcon`), active card highlight (`extractionCardActive`), status badge (`ImportStatusBadge` correctly showing spinning `extracting` when in-flight), file metadata (file size, total pages, error alert), live progress percentage, smooth 6px rounded progress track (`--radius-full`), active phase indicator (PDF extracting, AI Vision with `Sparkles`, OCR, or rate-limit cooldown with `Clock`), and a bottom action footer (`extractionFooter`) hosting the responsive cancel button with disabled `"Cancelling..."` feedback.
  - `ImportReviewView.tsx` — Review step: a review-level toolbar rendered above the panes in **every** view mode, plus the panes themselves.
    - **Review controls.** The toolbar carries the file selector, status badge, page tag, the `[ Split | Editor | Preview ]` `SegmentedControl`, and the AI cleanup accordion toggle button.
    - **Pane contents.** Lexical `WriterEditor` in Split/Editor, `MarkdownViewer` in Split/Preview, and the workspace-native `ImportDiffView` Git-style diff comparison with Accept/Reject (replacing the former modal dialog).
    - **Persistent notices.** The partial-extraction notice and the AI error are surfaced above the panes so they stay visible in every mode.
      - **Partial-extraction banner.** It is the shared `<Banner variant="warning" container="section">` keeping its `partial-extraction-banner` test id — the banner adapter forwards standard `<div>` attributes, so no bespoke div is needed.
      - **Diff toolbar isolation and lock.** When an AI cleanup diff is active (`isDiffActive = true`), the review toolbar's right controls (`reviewToolbarRight` — mode switcher and AI cleanup toggle) are hidden, and `ReviewFileSelector` is locked into a static read-only presentation (`disabled={isDiffActive}`) to prevent candidate switching and accidental loss of unaccepted diff work.
    - **Cleanup panel purpose.** To prevent accidental clicks and preserve vertical editor space on tablet and desktop, the AI Cleanup section is housed in a collapsible panel (`ReviewAiPanel`).
      - **Toggle.** It is toggled via the toolbar's `AI Cleanup` button (`aria-expanded`, `aria-controls="review-ai-panel"`); collapsed, the toolbar remains a clean single row.
      - **Expanded contents.** Expanded, it reveals the title/guidance hint, `AiModelPicker` (single-line tagline layout), and the `Run AI Cleanup` action button.
      - **Auto-expansion and collapse.** The panel auto-expands during in-flight operations (`isCleaning`) or active rate-limit cooldowns, and auto-collapses on candidate switch.
    - **File switching (Option B).** The permanent `Files` sidebar is gone so the panes keep the full width, and the toolbar's info block is now the selector.
      - **Single candidate.** Renders a static icon + filename.
      - **Several candidates.** Render a trigger (`resume.pdf (1 of 3) ▾`, `aria-haspopup="listbox"` + `aria-expanded`) whose popover (`role="listbox"`, `aria-label="Select file to review"`) lists every candidate with file icon, `ImportStatusBadge`, and a degrades-to-nothing page tag.
      - **Option selection.** Options are `role="option"` with `aria-selected`; picking one selects it, closes the popover, and returns focus to the trigger.
      - **Popover dismissal.** Dismissal is a document `pointerdown` outside trigger/popover or `Escape`.
      - **Listbox keyboard limit.** Options are tabbable, but arrow-key navigation inside the listbox is **not** implemented yet.
    - **Responsive review contracts (mobile, `<= 768px`).**
      - **Edit mode.** `viewMode` initializes to `'edit'` mode to maximize typing space on small screens.
      - **Mode control.** `SegmentedControl` switches to `layout="fill"` within a full-width wrapper (`reviewModeControlWrapper`) to eliminate dead space.
      - **Toolbar controls.** `reviewToolbarRight` and `AiModelPicker` (`layout="stacked"`) stack vertically with a 100%-width AI Cleanup action.
      - **Split panes.** `reviewBody` stacks panes vertically (`flexDirection: 'column'`) when `'split'` is active to avoid horizontal squeezing.
      - **Toolbar info.** `reviewToolbarInfo` uses `flexBasis: 'auto'` / `flexGrow: 0` on mobile to avoid blank space above the file title.
  - `ImportDiffView.tsx` — Workspace-native Git-style AI cleanup diff comparison view (replaces the modal dialog). Features a sticky review bar (`AI Cleanup Diff Comparison`, `+` additions and `-` deletions line counter pills, `[ Split Diff | Unified Diff | Preview ]` format toggle, `Keep Original` reject action, and `Accept AI Cleaned` accept action), line-by-line diff with gutter line numbers, red removal rows (`-`), green addition rows (`+`), and preview mode. Completely eliminates accidental modal dismissals, screen clipping, and lost work. **Responsive diff fallback (Sep 2026):** Automatically derives `effectiveMode` on mobile viewports (`<= 768px`) so when `displayMode === 'split'`, it gracefully falls back to `unified` diff and highlights the Unified Diff tab (omitting the unsupported Split Diff tab on small screens), completely preventing empty/blank diff view containers upon viewport resize or mobile loading.
  - `MaterialDetailsView.tsx` — Title assignment step: one Card surface per candidate (document icon, filename, file size, word count, and page count when the extraction knows it), with the `Material Details` `h3` kept verbatim as an E2E contract, accompanied by a descriptive subtitle (`detailsSubtitle`). Each card separates the file metadata row from the title input with a subtle divider (`detailsDivider`). The title field uses the shared `Input` configured with `label="Material Title"`, candidate placeholder, accessibility `aria-label` (`Material Title for <filename>`), and a helper hint (`detailsHint`) indicating its library and study visibility. Default candidate titles have their file extensions cleanly stripped across all extraction adapters and use cases. Word count comes from the extraction stats when present and is otherwise estimated from the current markdown (whitespace tokens carrying a letter or digit). It deliberately owns **no** commit action — the wizard footer owns `Save to Library`.
  - `ImportResultView.tsx` — R1 study handoff surface: a neutral centred column (max 520px) with one 56px `--color-success-muted` badge, an `h2` (`Import Successful`) plus count line, and one row per material (accent icon tile, ellipsised title, `Saved to Library` status, `ghost` Open Material action). The saturated success card is gone — `--color-success(-muted)` now marks only the badge and each row's status, where it describes the object instead of colouring the surface. Row actions are `ghost` so the deck keeps the single `primary` (`Open in Workspace`, single material only).
- `utils/`
  - `textDiff.ts` — Line-by-line diff computation utility: uses prefix/suffix trimming and Longest Common Subsequence (LCS) to generate unified diff lines and aligned side-by-side rows with additions and deletions counts.
- `hooks/`
  - `useImportSession.ts` — 5-step state machine with bounded concurrency (max 2 concurrent extraction jobs), candidate in-flight status tracking (`status: 'extracting'`), `ocrEngine` selection, progress tracking (`progressMap`), queue draining, candidate reset (`retryCandidate`), and `AbortController` cancellation per candidate (`cancelExtraction`). Guarantees clean exit transitions: moves to `'review'` only on completed normal extraction; on user cancellation, cleanly halts and returns to `'selecting'` without jumping to Review, preserving partial extraction results on the candidate for explicit user action. Adheres to pure state updater invariants using `candidatesRef` synchronized via `useEffect`.
  - `useAiCleanup.ts` — Opt-in AI markdown cleanup hook managing whole-document cleanup, selection-based cleanup (`cleanSelection`), section-by-section progress (`progress`), candidate-switching abort, rate-limit cooldown, and mid-run failure resumption (`retryRemaining`).
  - `useImporterContext.ts` — Dependency injection consumer for application use cases.
- `styles/importer.stylex.ts` — StyleX styles for the step body, drop zone wrapper (`dropZoneWrapper`), drop zone, extraction engine card (`engineCard` / `engineInfo` / `engineLabel` / `engineHint` / `engineControlWrapper`), file cards and extraction cards (`fileCard`, `fileActions`, `extractionCard*`, `fileIconTile*`, `extractionViewHeader`, `extractionTitle`, `extractionSubtitle`, `extractionCounterBadge`, `extractionProgressMeta`, `progressPercent`, `phaseIndicator*`, `fileErrorText`), the progress bar (`progressContainer` / `progressBar`), the status badge set (`badgedot` / `dot` / `badge*` / `dot*`), the pinned wizard action bars (`actionBar` + `actionBarEnd` / `actionBarSplit`), the review shell (`reviewShell` / `reviewToolbar*` / `reviewBody` / `reviewCenter` / `reviewRight` / `pageTag`), the file selector (`fileSelectorTrigger` / `fileIndex` / `fileKindIcon` / `popover` / `popoverItem*` / `popoverFilename`), the Git-style diff comparison (`diffShell` / `diffReviewBar` / `diffReviewHeader` / `diffReviewTitle` / `diffStats` / `diffStatAdd` / `diffStatDelete` / `diffActions` / `diffViewContainer` / `diffSplitColumns` / `diffPane` / `diffPaneHeader` / `diffCodeBody` / `diffLineRow*`), the details cards (`detailsHeading` / `detailsSubtitle` / `detailsCard*` / `detailsDivider` / `detailsHint`), and the results view (`resultContainer` / `successHeader` / `successBadge` / `resultTitle` / `resultSubtitle` / `resultMaterial*` / `resultActionDeck`). `iconSpin` is a StyleX `keyframes` spin with a `prefers-reduced-motion` off-switch — the retired `className="animate-spin"` was a Tailwind leftover the project never defined, so spinners were static. Every colour is an Astryx role token (`var(--color-*)`); no literal hex lives here — the one deliberate exception is the file-selector popover's elevation `boxShadow`, which uses a literal translucent rgba because the theme's shadow scale is tuned for cards (the app's other floating surfaces, `ActionMenu` and the compact-collections popover, do the same). Borders carrying a token are written as longhand triplets (`borderWidth` / `borderStyle` / `borderColor`) because StyleX drops a `border*` shorthand whose value contains `var()`. Radii come from the theme's own scale — `--radius-full` for circles/pills, `--radius-element` / `--radius-container` for surfaces; **`--radius-sm`/`--radius-md`/`--radius-lg` do not exist in `lunaclairTheme`** and an undefined radius token drops to the initial value (square corners) rather than degrading.

## Local Contracts

- Importer is code-split and lazy-loaded via `React.lazy` behind `/import` route to keep main app bundle lean.
- Primitive-only chrome: the wizard and its step views render the shared adapters (`Page`, `Button`, `Input`, `SegmentedControl`, `Dialog`) instead of raw `<button>` / `<input>` / bespoke overlay markup, and reference colour by role token — never a literal hex. The file-selector popover is the one exception: it needs `role="listbox"` / `role="option"` rows carrying icons, badges, and page tags, which no shared adapter provides (the shared `Selector` is a labelled combobox with plain string options, and `ActionMenu` is an icon-only ellipsis menu). If a generic popover/listbox primitive ever lands in `src/shared/ui`, fold this onto it.
- Status badges are the canonical `badgedot` pattern (`ImportStatusBadge`) and only ever use the sentiment roles `--color-{success,warning,error}` plus accent for in-flight work; `--color-danger` does not exist in Astryx and must not be introduced.
- Non-destructive re-entry: extraction only ever targets `pending` / `error` candidates (`useImportSession.startExtraction` filters the queue), so returning to Files and re-running the step can never discard markdown edits or accepted AI cleanups. Step 1's primary action is derived from candidate state by the screen layer (`src/app/screens/importer/utils/selectingAction.ts`) to keep that promise visible in the label.
- The review step's AI cleanup action keeps its state in the accessible name (`AI Cleanup (12s)` / `Cleaning with AI...`), so the countdown and in-flight state stay available to assistive technology, not just visually.
- Direct-path feature contracts only (ADR-010): consumes `WriterEditor` from `src/features/writer/components/WriterEditor`, `MarkdownViewer` from `src/features/reader/components/MarkdownViewer`, and `useAiModelSelection`/`AiModelPicker` from `src/features/ai/`.
- Concurrency limit: extraction queue runs with a maximum of 2 parallel worker jobs to avoid browser memory pressure.
- User-in-the-loop: AI cleanup is strictly opt-in and renders an in-workspace Git-style diff (`ImportDiffView`) with line-by-line additions/deletions; AI never silently modifies extracted text without explicit Accept. Candidate switching cancels in-flight cleanup and clears diff state; candidateId and original text must match upon acceptance. No modal dialog is used, completely preventing accidental backdrop clicks or Escape dismissals from discarding cleaned text.
- Multimodal Vision Extraction: AI Vision (`ukisai-swift-max`) digitizes scanned PDFs/images directly into structured Markdown tables and formatting. Importers execute AI Vision strictly on `ocrEngine === 'ai-vision'` with zero silent fallback to local Tesseract, emitting `phase: 'ai-vision'` extraction progress and separate `visionPages` statistics. Enforces 12-second pacing between request starts and abortable rate-limit cooldown (429 `retryAfterSeconds`, retrying up to 2 times).
- Cancellation & Partial Result Contract: On user cancellation, ongoing extraction preserves all pages extracted up to page `i-1`, marks `isPartial: true`, and returns cleanly to Step 1 (`selecting`). Users are offered explicit choices on the candidate card and bottom action bar (`Review Partial Extraction` or `Retry`), eliminating automatic navigation and screen flashing.
- Local-first offline invariant: Tesseract WASM is the default offline-capable extractor; AI Vision is strictly an opt-in cloud enhancement requiring `navigator.onLine` and MAX availability.
